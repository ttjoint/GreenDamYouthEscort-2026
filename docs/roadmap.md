# 实施顺序：从当前状态到可交付的安装包

本文回答三个问题，按顺序：**现在到底缺什么**、**按什么顺序补**、**每步怎么算做完**。

写作时间 2026-10。所有"现状"结论都可以用文中的命令重跑验证；
`docs/status-checklist.md` 是逐项状态表，本文是**顺序与依赖**，两者不重复。

---

## 1. 现状的一句话版本

**判定层完整，装配层空缺，交付层为零。**

- `src/green_dam/`（引擎）**已无待做项**：1,679 项测试全绿。
- `host/`（宿主）**每个零件都能用**，但没有一个进程把它们装在一起。
- 没有安装包、没有 exe、没有服务宿主、没有托盘。
- 控制台能跑，但**只读**——它显示状态，改不了任何东西。

### 1.1 三个零件，零个装配者

这是当前最要紧的事实，也是排序的起点：

| 组件 | 代码状态 | 谁启动它（生产代码） |
|---|---|---|
| 代理 `host/proxy/` | `ProxyServer` + `serve_forever_in_thread` 就绪 | **没有人** |
| 评分服务 `host/imaging/service.py` | `python -m host.imaging` | 家长手工 |
| 控制台 `host/ui/` | `python -m host.ui` | 家长手工 |

验证：

```bash
grep -rn "host.proxy.server import" --include=*.py host/ | grep -v tests
# 空：没有任何生产代码 import 代理
```

代理写得再好，不被启动就是一个库。这不是"缺一个功能"，是**缺一层**：
一个进程负责把三个组件按正确顺序拉起来、盯着它们、挂了自己重启。

### 1.2 控制台是只读的（刻意，但现在挡路）

`docs/host-layer.md` §2.10 记了理由：每个写操作都走 CLI，因为 CLI 进日志、
可复现、可审计；一个 POST 端点需要 CSRF 防护和第二条审计路径。

理由成立，但代价现在显出来了：**家长装完软件后，用 GUI 改不了任何设置**。
"用 GUI 看状态、用命令行改设置"不是一个可交付的产品形态。

### 1.3 一个未被记录的功能缺口：代理从未指向浏览器

`host/policy/__init__.py` 会写 `ExtensionInstallForcelist`（强制装扩展），
但**没有任何代码把浏览器配置成走本地代理**。没有 `ProxyMode` / `ProxyServer`
策略项，也没有 PAC 文件。

意味着：即使今天把代理启动起来，浏览器也不会用它。
扩展路径（DOM 过滤 + 图像）不依赖代理，所以**产品今天能做的是扩展能做的那部分**；
代理能做的（拦请求、查响应体）目前完全没生效。

## 2. 关于"可选分类部署的安装包"

**问题**：功能完整版装 Program Files + 专用账号，另允许降级部署——
是否要做一个安装包，在里面提供可选的分级部署？

**答案：要一个安装包，但不要"安装时选功能"。**

理由分开说。

### 2.1 一个安装包，不是两个

两个安装包（完整版 / 精简版）意味着两条测试路径、两份文档、两种 bug 报告，
而它们的差别只有 22 MB（模型权重）。一个包，用组件勾选控制。

### 2.2 但要区分两种"可选"，它们的性质完全不同

这是关键区分，容易混：

| 类型 | 例子 | 安装时可选？ | 为什么 |
|---|---|---|---|
| **形态** | Program Files vs 便携 | ✅ **可以** | 纯路径差异，同一份代码 |
| **形态** | LocalSystem vs 专用账号 | ✅ **可以** | 纯账号差异，同一份代码 |
| **组件** | 装不装图像模型 | ⚠️ 可以，但**默认必须勾上** | 纯数据差异 |
| **组件** | 装不装屏幕 OCR | ❌ **不做**（见 §2.4） | 功能没实现 |
| **功能** | 装完再决定要不要代理 | ❌ **不做** | 见 §2.3 |

### 2.3 功能开关不能放在安装时

安装时的选择有一个坏性质：**家长无法在事后知道当时选了什么**，
而且选错了要重装才能改。

所以功能开关一律放在**运行时**，不放在安装时：

- 图像过滤开关 → 控制台 / `green-dam words` / 策略槽 13
- 词库包 → `green-dam words enable/disable`（运行时，立即生效）
- 进程监控 → 策略槽 + 控制台

安装程序只做一件事：**把文件放到位、注册服务、写 ACL**。
它不做功能决策。这条规则让"我装的时候选了什么"这个问题永远不需要被回答。

### 2.4 屏幕 OCR 不在勾选列表里

M5 已决定不做（全屏 OCR 等于录屏，`host-layer.md` §2.7）。
安装包里出现一个装不上的选项，比没有这个选项更糟。

### 2.5 安装程序要提供的勾选（最终清单）

```
[x] 图像过滤（21.4 MB 模型）        ← 默认勾选，可取消
[x] 浏览器扩展                      ← 默认勾选
[x] 安装为 Windows 服务              ← 默认勾选；取消则降级为"当前用户手动启动"
[ ] 便携模式（不注册服务、不写 ProgramData）  ← 默认不勾
```

形态与账号由安装程序按 §2.5 的选择推导，**不让用户直接面对
"LocalSystem 还是专用账号"这种问题**——那是实现细节，家长不该被问。

## 3. 实施顺序

排序依据只有一条：**先让东西能跑起来，再让它好装，最后让它好用。**
反过来做（先做 GUI 再做装配）会得到一个漂亮的界面控制着一个没启动的代理。

每步都标注了**验收标准**——不是"代码写完"，是"能证明它工作"。

### 阶段 0：先把三个零件装成一个（最要紧）

| # | 任务 | 依赖 | 验收标准 |
|---|---|---|---|
| **0.1** | `host/supervisor.py`：一个进程按序启动代理 + 评分服务，任一挂掉按退避重启 | — | 杀掉评分服务线程，3 秒内自动重启；`test_supervisor.py` |
| **0.2** | 代理接线：`supervisor` 用固定端口启动 `ProxyServer` | 0.1 | 真实浏览器经代理访问一个被拦 URL，得到拦截页（真机测试，不是单测） |
| **0.3** | `host/__main__.py`：`python -m host` 启动全部 | 0.1 | 一条命令起全套，Ctrl-C 干净退出 |

**为什么 0.1 排第一**：它把"三个库"变成"一个产品"。在它完成之前，
任何 GUI 工作都是在给一个不会自己启动的东西做界面。

### 阶段 1：让代理真正生效

| # | 任务 | 依赖 | 验收标准 |
|---|---|---|---|
| **1.1** | 浏览器代理策略：`ProxyMode=1` + `ProxyServer=127.0.0.1:PORT` 写入 Chromium/Firefox | 0.2 | 装完策略后新开浏览器，`netstat` 显示流量经本地端口 |
| **1.2** | PAC 或固定端口的选择与记录 | 1.1 | 文档说明为什么选它；固定端口需处理端口占用 |
| **1.3** | 服务退出时代理优雅关闭（否则浏览器失去网络） | 0.2 | 停服务后浏览器立即恢复直连，不需要重启浏览器 |

**1.3 是最容易漏的一条**：代理进程消失而浏览器还指向它，等于**断网**。
这是"保护软件把电脑搞坏"的经典形态，必须显式处理。

### 阶段 2：GUI 从只读变成可用

| # | 任务 | 依赖 | 验收标准 |
|---|---|---|---|
| **2.1** | 控制台加写操作框架：POST + CSRF token + 审计日志 | 0.3 | 每个写操作同时产生一条日志；`test_ui_write.py` |
| **2.2** | 改密码页 | 2.1 | 改密码后旧密码失效、新密码可用 |
| **2.3** | 词库开关页（当前只读列表 → 可勾选） | 2.1 | 勾选后引擎立即生效，无需重启 |
| **2.4** | 策略开关页（图像过滤、进程监控等） | 2.1 | 改动落到 `xconfigs.dat` 并写日志 |
| **2.5** | 托盘图标（`pystray`）：状态、打开控制台、暂停 | — | 关闭控制台窗口后托盘仍在，代理仍运行 |
| **2.6** | 首次运行向导：装扩展 → 选词库 → 设密码 | 2.2 2.3 | 全新机器走完向导后状态页全绿 |

**2.1 是这阶段的真正工作量**，2.2–2.4 都是它的应用。
`host-layer.md` §2.10 说"在没有屏幕需要它之前不加"——
现在有屏幕需要它了，所以要加 CSRF 防护和第二条审计路径，不能直接开 POST。

### 阶段 3：服务宿主与 ACL（H3）

| # | 任务 | 依赖 | 验收标准 |
|---|---|---|---|
| **3.1** | `host/service.py`：`win32serviceutil` 包装 `supervisor` | 0.3 | `sc start GreenDam2026` 后全套运行 |
| **3.2** | 专用虚拟账号 + 最小权限 ACL | 3.1 | 用专用账号能跑；`processes.py` 的 `AccessDenied` 报告为 0 |
| **3.3** | 恢复动作：崩溃自动重启（1/2/5 分钟退避） | 3.1 | 杀进程后服务自动回来 |
| **3.4** | 安装日志（`journal/install.json`）记录每一项可回滚变更 | 3.1 | 卸载后无残留（B11） |

**3.2 的顺序不能提前**：ACL 配在错误的路径上，会得到"某个功能静默失效"
——`host/processes.py` 会报告 `AccessDenied`，但家长看到的是"进程监控不工作"。
先有 3.1 的服务骨架，才有地方验证 ACL。

### 阶段 4：安装包

| # | 任务 | 依赖 | 验收标准 |
|---|---|---|---|
| **4.1** | 打包 exe 入口（`pythonw.exe` + `host/__main__.py`，无控制台窗口） | 0.3 | 双击 exe 启动，无黑框 |
| **4.2** | Inno Setup 脚本：文件、服务注册、勾选项、卸载 | 3.1 4.1 | 全新 Windows 装完即可用 |
| **4.3** | 便携模式（自解压，不注册服务） | 4.2 | 解压即用；控制台显示"便携模式：进程监控不可用" |
| **4.4** | 卸载执行（`cli_lifecycle.cmd_uninstall` 接进安装程序） | 3.4 | 卸载后 `%ProgramData%`、注册表、防火墙规则全清 |
| **4.5** | 签名与校验（可选，取决于分发方式） | 4.2 | — |

**4.1 排在这里的原因**：exe 入口需要 `supervisor` 已经存在，
否则打出来的是一个只能显示状态的 exe。而 Inno Setup 需要服务已经能注册。

**工具现状**（本机实测）：

```
iscc / makensis / pyinstaller / nuitka   全部未安装
D:/_Temp/bundle_cache/python-3.12.6-embed-amd64.zip   已缓存
```

即：4.1 之前需要先装打包工具链，或改用已缓存的嵌入版 Python
（`tools/package.py` 已支持 `--embeddable`）。

### 阶段 5：全系统验收

| # | 任务 | 验收标准 |
|---|---|---|
| **5.1** | 全新 Windows 虚拟机：装 → 用 → 卸，全程记录 | 每一步都有截图或命令输出 |
| **5.2** | 真机浏览器测试：Chromium + Firefox，扩展 + 代理 | 两条路径都能拦 |
| **5.3** | 降级路径测试：无模型 / 无网络 / 无管理员权限 | 每种都"功能受限但可用"，不是崩溃 |
| **5.4** | 权限矩阵实测：填 `host-layer.md` §2.13 的表 | 表格每一格都有实测依据，不是推理 |
| **5.5** | 文档与实现一致性终审 | `pytest` 全绿 + 人工过一遍 `docs/` |

## 6. 现在就能做的三件事

如果只能做三件：

1. **`host/supervisor.py`（0.1）** —— 把三个库变成一个产品，其他一切都依赖它。
2. **代理优雅关闭（1.3）** —— 防止"装了保护软件之后断网"。
3. **控制台写框架（2.1）** —— 让 GUI 从展示品变成工具。

前两件是**防止产品有害**，第三件是**让产品可用**。
三者都比"再多写点测试"更值得做——测试已经很厚，装配是空的。
