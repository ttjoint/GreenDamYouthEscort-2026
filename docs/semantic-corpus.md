# 语料实测记录

这一篇记录**判断机制实测**：我们造了语料，拿数据表去跑，看结果对不对。
写它的原因是过程中有三个预期被数据推翻，如果只看结论会以为一切顺利。

## 先纠正一个错

最初我把 `hong_hei` 当成完整的敏感度分级，理由是按值分组后主题高度一致：

| `hong_hei` | 词条 |
|---|---|
| 7 | 大纪元网址、新闻网 |
| 6 | 学员供稿、弟子报道 |
| 5 | 《九评》系列、610 恐怖组织 |
| 4 | 4.25 上访、邪教组织、领导人名 |
| 3 | 610 办公室、洗脑班 |
| 2 | 大法弟子、非法判刑 |
| 1 | 非法聚集、发正念、变体拼写（`a4Lu4`、`A--Lun--Gong`） |

看起来无懈可击，于是写下预期：「《九评共产党》必然是 5～7 级」。**实测是 0。**

去查数据，全部 49 个含「九评」的词条，`hh` **无一例外都是 0**。同样地，
「610」的短词条几乎都是 0，只有 `y省yy县610恐怖组织的犯罪事实` 这种长句才是 5。

所以 `hong_hei` 的语义比我假设的窄得多。它更像「该词条在语料表中的优先级」，
而 0 是绝大多数词条的默认值。4,692 条 sense 里只有 516 条非零。

这不是解码错误——`hh=0` 的词条确实存在且有完整上下文。是我把数据想简单了。

## 数据实际是什么

`FalunWord.lib` 解开后，字符池是一段 **36,943 字符的连续敏感语料流**，
按拼音/字母序排列：

```
恶党书记我坐在他的小腿上在中共治下的中国"610"歹徒"大法弟子""大纪元"网站
"法轮大法""法轮功"弟子"法轮功"头目"法轮功"邪教"法轮功"总部"六四"屠杀
"明慧"网"三个呆婊","与时俱尽""三个代表"腐败大业"要人权,不要奥会"'法轮功'
'三去''](法)(轮)(法轮功)呼吁(江XX)(学)(员)*法*仑*功*2005年《九评》出来
4-25集体上访4.25非法聚集事4.25前后发正念4.25上访事件5.13世界法轮大
6.10邪恶组织6.12办公室610、公安的邪恶之徒... 
```

sense 表的 `off` 是 **100% 单调递增**的（4,692/4,692），证实它就是在扫这段文本。

所以三层结构是：

```
字符池        一段连续语料
sense[i]      (off, len, hh)  —— 语料上的一个片段
链节点         该片段的子串，用于实际匹配
```

`hh` 挂在 sense 上，也就是挂在**片段**上，而不是挂在单个字符上。

## 第二个坑：等级该跟谁走

第一版实现从 `sense["text"]`（池切片）取等级，结果「《九评共》」这类命中全是 0 级。

原因是 `term_senses`（链→sense 的引用）和 `senses`（池位置表）是两套视图。
`《九评》` 作为池切片全是 0 级，但**链引用它的那条**可以有别的等级。
等级要跟链词条走。

改过来之后命中的种类从 3,364 涨到 10,182，`大纪元新` 的 7 级、「大法弟子」的
6 级这才出现。

## 同一字符串有多个等级

3,364 个唯一片段里，43 个带多个等级：

```
'大法弟子'  -> [6, 0, 0, 0, 0, ...]        6 次高等级，其余 0
'《法轮功'  -> [1, 0, 1, 5, 5, 5, ...]     随上下文浮动
'4.25'      -> [1, 4]
```

这正是原引擎「上下文敏感」的物理载体：**等级不是词的属性，是词在某段
上下文中的属性**。复刻时保留全集、取最高值作保守判定，把决定权交给策略层。

## 语料与结果

12 条自造语料，三类用途：

| 类别 | 断言什么 | 结果 |
|---|---|---|
| `safe`（5 条）| 日常文本必须零命中 | 5/5 通过 |
| `known`（4 条）| 具体等级值，回归防护 | 4/4 通过 |
| `weak`（3 条）| 「命中但等级低」，记录数据真实形状 | 3/3 通过 |

`weak` 那三条就是刻意保留的反直觉案例。如果哪天有人"修正"了数据让
`《九评共产党》`变成 5 级，这三条测试会失败——那时应该问的是
「谁改了数据」，而不是「测试怎么错了」。

## 结论

**能做到**：词条匹配、位置定位、等级提取、多等级保留、最长优先、无重叠。
10,182 个可匹配词条，35 项测试通过。

**做不到的，说清楚**：

1. 原引擎逐词「正常/拦截」的标志来自 `FMean.tmp`，该文件从未随包分发
   （`falunword-format.md` 有反汇编证据）。这里重建的是**基于可用等级的
   判定梯度**，不是位级还原。
2. `hong_hei` 的完整语义仍未确定。它是真实数据，但覆盖面窄（516/4692），
   且「九评」这类核心词条等级为 0，说明它**不是**一套自洽的敏感度分级。
   剩余语义可能要结合 `SentenceObj.dll` 里尚未逆向的语法规则才能解释。
3. HNC 的语法层（`MakeObjFromJK`→`MakeObjFromSri` 的概念网络推导）只反出了
   词性映射表（`0x30→0x31/0x32/0x34` 这类分层编码），语法规则本身未还原。

把这三条写进文档，是因为一个不能说明边界的"复刻"等于说谎。
