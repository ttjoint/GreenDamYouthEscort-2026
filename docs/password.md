# 家长密码（I6 已实现）

`src/green_dam/secret.py`。测试 `tests/test_secret.py` 33 项 +
`test_cli.py::PasswordCliTest` 7 项。

## 1. 放置位置的决策（写代码前先分析）

密码哈希有三个候选位置，逐条评估：

| 候选 | 评价 |
|---|---|
| `config.py` | ❌ 配置是**数据格式**，密码是**安全原语**。混在一起会让每个读配置的代码都接触秘密 |
| `eventlog.py` | ❌ 已用 `hashlib`，但那是内容摘要（单向、无需校验），语义完全不同 |
| **新模块 `secret.py`** | ✅ 单一职责：认证秘密的存储与校验 |

判断依据：**密码涉及三个别处没有的失败模式**——

| 失败模式 | 后果 | 本模块的处理 |
|---|---|---|
| 比较时序 | `==` 提前返回，逐字节泄漏摘要 | `hmac.compare_digest` |
| 盐管理 | 缺盐或复用盐会静默削弱哈希 | 记录自带盐与参数，缺了就无法构造 |
| 参数升级 | PBKDF2 迭代数会随年代上升 | 记录保存创建时的迭代数，旧记录仍可验证 |

这些放进 `config.py` 意味着**每个读配置格式的人都得处理秘密**。放在独立模块，
配置层永远看不到密码。

## 2. 原厂做了什么，本实现做了什么

原厂在二进制里**硬编码密码**（七位数字字面量，`gn.exe@0x4d288` 与
`XNet2.exe@0x4d48c` 仍在）。硬编码的秘密不是秘密：拿到安装包的人都有。

本实现：

- **没有默认值，没有回退**。无密码记录时，所有特权操作一律拒绝
  （`NoPasswordSet`），而不是接受一个已知密码。
- `tests/test_secret.py::NoDefaultTest` 断言模块里**不存在任何七位数字字面量**
  ——那正是原厂硬编码密码的形状。

## 3. 格式

```
$pbkdf2_sha256$<iterations>$<salt-b64>$<digest-b64>
```

与 Django 同形，便于复用现有工具和直觉。

| 参数 | 值 | 说明 |
|---|---|---|
| 算法 | `pbkdf2_sha256` | 架构 §M7 指定 |
| 迭代数（新建） | **600,000** | OWASP 2023 对 PBKDF2-SHA256 的下限 |
| 迭代数（最低接受） | 100,000 | 低于此的记录视为被篡改，拒绝 |
| 盐长度 | 16 字节 | RFC 推荐 |
| 摘要长度 | 32 字节 | SHA-256 输出 |

**为什么是 600,000 而不是更高**：这是桌面应用登录路径上的操作，是明确的
折衷，写在常量注释里而不是藏着。`needs_rehash` 让更强的参数在下次成功登录时
自动升级。

## 4. 常量时序比较

```python
candidate = _derive(password, record.salt, record.iterations)
return hmac.compare_digest(candidate, record.digest)
```

`==` 会在第一个不同字节处返回，泄漏"匹配了多少"。攻击者据此可逐字节恢复
摘要。`compare_digest` 不短路。

测试用**结构性断言**（源码里有 `hmac.compare_digest`）而非行为计时——
后者在 CI 里不稳定，而我们真正能控制的是"调用了正确函数"。

## 5. `repr` 不打印盐和摘要

```python
def __repr__(self):
    return f"PasswordRecord(algorithm={...!r}, iterations={...})"
```

`repr` 会进 traceback、日志、bug 报告。摘要不是密码，但它是**离线攻击者
想要的东西**，所以不进日志。

这与 `Finding.__repr__` 的修正是同一原则（见 `docs/structure-audit.md` §5b）。

## 6. 原子写入 + 权限

```
同目录临时文件 → 写入 → fsync → os.replace
```

文件以 `0o600` 创建（POSIX 上生效，Windows 上忽略）。测试断言目录里无
`.tmp` 残留、覆盖写会替换而非追加。

## 7. 诚实的边界

架构 §M7 明确写了：**管理员总能绕过**——替换文件或停服务即可。目标是
"非管理员不能随手绕过"，这是可达成的、合法的、且足够的。

本模块不假装更多。

## 8. CLI

```bash
green-dam password generate --length 20    # 生成随机密码（用 secrets，不是 random）
green-dam password set --path parent.pw    # 交互式输入（不回显）
green-dam password verify --path parent.pw
green-dam password show --path parent.pw   # 只显示算法与迭代数
```

密码通过 `getpass` 提示输入，不走命令行参数（命令行会进 shell 历史和进程列表）。
测试断言**任何子命令都不回显密码**。

## 9. 验收（40 项）

| 组 | 覆盖 |
|---|---|
| 无默认值 | 无七位数字字面量、空密码拒绝、文件缺失/为空都拒绝 |
| 哈希 | 算法名、迭代下限、摘要长度、盐随机、同盐同摘要、不同密码不同、Unicode、短盐/错长度/弱迭代拒绝 |
| 验证 | 正确/错误/大小写/空、`compare_digest` 结构性断言 |
| 序列化 | 往返、格式形状、错误前缀/字段数/非整数/坏 base64、**篡改成弱参数仍拒绝** |
| `repr` | 不含盐与摘要 |
| 重哈希 | 弱记录需要、当前不需要 |
| 存储 | 存读、建父目录、无临时残留、覆盖、POSIX 权限 |
| 生成 | 长度、过短拒绝、随机性 |
| CLI | 生成/设置/验证/查看、错误密码退出码 1、**不回显密码** |
