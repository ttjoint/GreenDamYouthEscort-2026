# M2 网络层：判定链（已实现）与传输层（待做）

本文件只讲**判定逻辑**。传输（代理、防火墙、TLS 中间人）见
`architecture.md` §M2 的四段降级，本文不重复。

## 1. 已实现：`src/green_dam/intercept.py`

判定链是纯逻辑，不碰 socket。传输层将来只负责**填 `Request` 字段**。

```python
Request(direction, process=None, port=None, host=None, prefix=b"", body=None)
    ↓
Interceptor(lists=NameLists()).decide(request)
    ↓
Decision(outcome, stage, reason, detail="")
```

字段缺失就跳过对应阶段，**不猜**。这是四段降级能复用同一份判定的原因：
第 1 段只填 `host`，第 3 段才填 `body`。

## 2. 阶段顺序（原厂顺序，有证据）

`analysis/probe/p17`、`p19` 实测：原厂按此顺序检查，**首个命中即停**。

| # | 阶段 | 出站 | 入站 | 依据 |
|---|---|---|---|---|
| 1 | 进程 | ✔ | ✔ | `p17` 0x10003499 Toolhelp 遍历 |
| 2 | 地址/端口 | ✔ | ✔ | `p17` 0x1022806c 表 |
| 3 | 协议指纹 | ✔ | — | `p18` 0x10005678 URL 提取 |
| 4 | 主机/URL | ✔ | ✔ | `p18`/`p19` |
| 5 | 内容 | ✔（提取 URL） | ✔（关键词规则） | `p18`/`p19` |

顺序是**有意义的**，不只是效率：它决定日志里记的是"因为进程被拦"还是
"因为内容被拦"。因此 `Decision.stage` 是一等字段，测试专门钉住"谁优先"。

## 3. 动作语义

| 方向 | 动作 | 依据 |
|---|---|---|
| 出站 | 返回 0 + errno **10054**（`WSAECONNRESET`） | `p17` |
| 入站 | 替换响应体（不直接断连） | `p19` |

`Decision.errno` 只对出站阻断给出 10054。入站的"替换响应"属于传输层动作，
本层只报告 `outcome=block`，由传输层决定怎么替换。

**为什么是 10054**：原厂故意让被拦程序以为"对端重置了连接"，而不是收到
一个明确的策略拒绝。这是隐蔽设计，复刻时保留 errno 值以便行为一致，但
**不保留隐蔽意图** —— 新实现的日志会明确写"被策略阻断"。

## 4. 端口集

入站关键词过滤只在 HTTP 端口上运行（`p19` 实测）：

```
{80, 81, 8080, 8081, 8888, 3128}
```

`HTTP_PORTS` 常量，测试钉住。

## 5. 二进制嗅探

原厂看前 10 字节里有没有 ≥ 0x80 的字节（`p19`）。这里表述为
"前 10 字节里有没有非可打印 ASCII"，等价且不硬编码字节数。

**关键设计**：二进制嗅探**不是独立阶段**。最初把它写成独立阶段并返回
`ALLOW`，会让"二进制响应 + 命中主机名单"被错误放行。现在它位于内容阶段
**内部**，只抑制关键词检查，不影响前面阶段已经做出的阻断。

这个错误是写测试时发现的，`test_binary_body_skips_content_but_host_still_blocks`
专门防止它回来。

## 6. 明确不做

| 项 | 理由 |
|---|---|
| 不实现代理/防火墙 | 属传输层，见 `architecture.md` |
| 不给信号强度打分 | 原厂 分→动作 映射未还原（见 `policy-layer.md` §2.1） |
| 不判断 HTTPS 能否解密 | 本层只消费 `body`，有就有、没有就没有 |
| 不还原隐蔽意图 | 保留 errno 值，但日志明确写"策略阻断" |
