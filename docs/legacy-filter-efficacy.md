# 原厂「不完整 HNC」的实际过滤效果（实测）

**一句话**：原厂这套东西，等于一个**只认 4,693 条固定搭配的字面匹配器**。
它的准确率来自词表小，不来自理解语义。

## 0. 先说清楚「原厂这套」到底是什么

`docs/engine-call-graph.md` 已经证明句类分析是死代码。那么真正跑起来的是什么？

```
Handler.dll
  ├─ CreateHncTextGroup("\\hnclib\\")
  │    └─ 加载 FalunWord.lib（5.5 MB）
  │         ├─ 第 1 层 trie     272,920 节点，142,742 个词条
  │         └─ 第 2 层 打分表    4,693 条，每条 (反动度, 红黑度)
  └─ CorpGroup(文本)
       └─ this-0x124 -> CFWordLib::MakeALC
            └─ SearchChar（trie 查找）
```

**没有句法分析，没有短语结构，没有词义组合。** 就是查表。

## 1. 三种用法实测对照

### 测试集

- **正样本 10 句**：法轮功/邪教相关，全部由打分表里的真实词条构成。
- **负样本 10 句**：完全无害的日常句子（天气、上班、开会、看书）。
- **真实小说 315 万字**（`D:\Docs\_w\小说` 前 3 个文件）。

### 结果

| 策略 | 做法 | 正样本命中 | 负样本误报 | 真实小说 |
|---|---|---|---|---|
| `trie_all` | trie 查到就算 | 10/10 | **10/10** | **582.8 次/千字** |
| `trie_len2` | trie ≥2 字算 | 10/10 | **10/10** | **123.9 次/千字** |
| `scored` | 只有打分表命中才算 | **7/10** | **0/10** | **0.003 次/千字** |

`trie_all` 在真实小说上**每个字命中 0.58 次**——等于全部拦掉。
`trie_len2` 每千字 124 次，也不可用。

### 为什么 trie 层不能用

`FalunWord.lib` 是**通用词库**，不是敏感词表。里面东西：

```
今天  公司  工作  同事  喜欢  孩子  火车  会议  消息  进展  节目
```

实测负样本被误报的原因：

```
他在公司负责财务工作，同事都很喜欢他
  -> 命中「公司」「工作」「同事」「喜欢」
今天天气不错，我们一起去公园看书吧
  -> 命中「今天」「天气」「公园」
```

`trie_len2` 命中 10/10 的具体证据：

```
全球公审江泽民    -> ['全球', '审江泽民']       ← 「全球」是普通词
天安门自焚案是栽赃 -> ['安门', '自焚案', '栽赃']
《转法轮》这本书…  -> ['《转法轮》', '这本书']    ← 「这本书」是普通词
```

**只要词库里有普通词，trie 层就必然误报。** 这是结构性问题，调不出来。

## 2. 打分表策略：0 误报，但漏 30%

### 命中详情

```
命中  大纪元时报今天发表了社论      ['大纪元']
命中  明慧网消息称有新的进展        ['明慧网消息']
漏掉  他是法轮功学员                              ← 见下
命中  退党保平安，快去看九评        ['退党保平安']
漏掉  610办公室下达了通知                          ← 见下
命中  真善忍好，法轮大法好          ['真善忍好', '法轮大法好']
命中  全球公审江泽民                ['全球公审江泽民']
漏掉  天安门自焚案是栽赃                          ← 见下
命中  《转法轮》这本书到处都在传    ['《转法轮》']
命中  新唐人电视台播出了节目        ['新唐人电视台']
```

### 漏掉的三个，原因全都一样

| 漏检句 | 为什么漏 |
|---|---|
| `他是法轮功学员` | 打分表里只有 `'法轮功'`（**带引号**）、`"法轮功"弟子` 等，**裸词 `法轮功` 没登记** |
| `610办公室下达了通知` | 打分表里有 `610歹徒`、`610邪恶`，没有 `610` 或 `610办公室` |
| `天安门自焚案是栽赃` | 有 `天安门自焚栽赃案`（连写），没有中间隔字的版本 |

**这就是纯词表法的死穴：词形不匹配就漏。** 它不理解
「法轮功」和 `'法轮功'` 是同一个东西，「610」和「610办公室」是同一个机构。

### 打分表为什么这么小、这么怪

4,693 条里 **287 条带引号/括号修饰**：

```
'法轮功'        (0,1)
"法轮功"弟子    (0,1)
[法轮功]        (4,4)
<<法轮功>>      (0,4)
```

这不是「规范词表」，是**某份具体文档里的原文片段**。
厂商大概是拿一批已判定为有害的文章，把里面出现的串切出来入库。

后果：

- 好处：误报极低（只认见过的原文形态）。
- 坏处：**换个写法就漏**，而且词表不能复用到别的场景。

## 3. 所以原厂的实际能力边界

| 能力 | 有没有 |
|---|---|
| 认出**见过的原文片段** | ✅ 极准（0 误报） |
| 认出**同义改写** | ❌ 完全不能 |
| 认出**换个词形**（加引号/去引号/加字） | ❌ 完全不能 |
| 认出**新的敏感内容** | ❌ 完全不能（没有词条就不认） |
| 理解**语义倾向** | ❌ 从未实现（句类分析是死代码） |

用一个比喻：它像一个**只会背答案的考生**。
背过的题（原文片段）一分不差，没背过的一律不会。

## 4. 那 HNC 论文里那套东西能补上什么

论文（`_hnc_theory.txt` / `_ccl99.txt` / `_hnc_class.txt`）描述的是：

1. **切词** -> 词性/词义
2. **切块** -> 主块（E/A/B/C）+ 辅块（Ms/In/Wy/Cn/Re/Pr/Rt）
3. **句类判定** -> 24 个句类码
4. **语义倾向** -> 对立统一性 / 褒贬 / 下级E的褒贬 / 相对立场
5. **作者立场原点** -> 这是「谁在说」

其中 **4 和 5 正是词表法做不到的**：

```
"法轮功"学员  ->  E=学员, 对象=法轮功, 褒贬=?   需要语义判定
法轮功学员    ->  同一个意思，只是少了引号     词表法漏掉
```

如果第 2–4 步能跑通，`法轮功` 后面跟任何名词都应该被识别为
「对象是敏感实体」，而不是靠穷举 `'法轮功'弟子`、`"法轮功"头目`、
`[法轮功]`……

**这就是我们按论文重做的理由。** 不是为了复刻产品，
是为了补上产品没做的那一半。

## 6. 诚实边界

- 正样本只有 10 句，是**我自己构造的**，不是独立标注集。
  它能说明「词形不匹配会漏」这个**机制**，不能当准确率。
- 真实小说用的是 3 个文件（315 万字），不是全量 47M。
  慢的原因是纯 Python 逐位置匹配，不是算法问题。
- `scored` 策略 0.003 次/千字不是「正好」——3 次命中里
  可能包含真正的巧合（比如某本小说里真提到过相关词）。
- **反动度/红黑度的数值语义仍然未知**，本测试只用了「命中/未命中」，
  没有用分数做任何事。

## 7. 对项目的结论

1. **复刻原厂不值得**：目标就是「背答案」，复刻出来也只能背答案。
2. **原厂架构有参考价值**：两层（trie + 打分）比单层词表好，
   因为 trie 负责「找到候选」、打分表负责「判定」，职责分离。
3. **论文那套是唯一增量**：语义块 + 句类 + 褒贬判定，
   才能处理 `法轮功学员` 这类未登记的写法。
4. **但论文那套现在跑不动**：`chunker.py` 退化率 41.4%，
   `Word.lib` 缺失，词义表全无。这是接下来要啃的。
