# 原始 HNC 过滤引擎的查询链路（实测打通）

**结论**：`SearchWord` 是完整的查询入口，返回值直接给出打分表下标。
整条链路已实测跑通，**4,683 / 4,693（99.8%）** 的打分表词条能被精确查回。

## 1. 两层结构

`FalunWord.lib` 不是一张平表，是**两层**：

```
第 1 层  trie（272,920 个字符节点）
           原子词：法轮功 / 邪教 / 明慧网 / 今天 / 公司 ...
           ↓ SearchWord 逐字符下降
第 2 层  打分表（4,693 条）
           组合短语：610歹徒 / "法轮功"弟子 / 大纪元 ...
           每条带 (反动度, 红黑度)
```

**实测：96.2% 的打分短语包含 trie 里的原子词**，两层是叠加关系。

## 2. `SearchWord` 的签名与语义

`?SearchWord@CFWordLib@@QAEPAVFCCharNode@@PAGHAAH@Z` @ **0x2550**

```c
FCCharNode* SearchWord(CFWordLib* this,  // ecx
                       wchar_t*   word,  // esp+4
                       int        len,   // esp+8
                       int*       out);  // esp+12
```

### 返回值 `out` 就是打分表下标

实测（32 位 Python 2.7 直调）：

| 查询 | `out` | 打分表对应 | (反动, 红黑) |
|---|---|---|---|
| `大纪元` | **808** | `entries[808]` = `大纪元` | (6, 3) |
| `法轮功` | `-1` | — | 无分数 |
| `明慧网` | `-1` | — | 无分数 |
| `江泽民` | `-1` | — | 无分数 |
| `今天` | `-1` | — | 无分数 |
| `610` | `-2` | — | trie 里没有 |

- `out >= 0`：命中打分表，值就是下标。
- `out == -1`：在 trie 里，但**没有分数**（普通词，或者只是更长短语的前缀）。
- `out == -2`：trie 里**根本没有**这个词。

### 全量校验

对 4,693 条打分表词条逐个调用 `SearchWord`，检查 `out == 自身下标`：

```
4683 / 4693 一致（99.8%）
```

10 条不一致的都是**重复词或相邻词条归并**（例如 `法轮大法好` 出现两次，
都归到 1125），属于 trie 的正常行为，不是错误。

## 3. 节点结构

```asm
; SearchWord 核心循环（0x25a0 附近）
0f b7 c0           movzx eax, ax          ; 当前字符
c1 e0 04           shl   eax, 4           ; *16（节点 16 字节）
8b 94 38 58 01 00 00  mov edx, [eax+edi+0x158]  ; 子节点表指针
8d 84 38 4c 01 00 00  lea eax, [eax+edi+0x14c]  ; 当前节点
...
e8 24 ff ff ff     call  SearchChar       ; 在子表里二分查找
```

节点（16 字节）：

| 偏移 | 含义 |
|---|---|
| `+0` | `u16` 字符值（实测 `法`=27861、`共`=20826、`今`=22825）|
| `+4` | 子节点表指针 |
| `+8` | 子节点数 |
| `+12` | **打分表下标**；`0xFFFFFFFF` = 无分数 |

`+12` 恒为 `-1`（`0xFFFFFFFF`）的节点就是纯中间节点。

## 4. 正确的过滤算法

```
对文本的每个位置 i：
    从最长可能长度往下试到 1：
        sub = text[i:i+L]
        node, out = SearchWord(sub)
        若 out >= 0：
            命中，记录 (sub, out, 打分表[out])
            i += len(sub)，跳出
    都不命中：i += 1
```

**关键**：只有 `out >= 0` 才算命中。`out == -1` 表示「trie 里有但无分数」，
不能当命中——否则普通词（`今天`、`公司`）会全部误报。

## 5. 三层数据的实际作用（实测）

| 数据 | 规模 | 能不能单独当词表 |
|---|---|---|
| trie 全部词条 | 142,742 | ❌ 含 73,236 个单字节点；普通词也在里面 |
| trie 长度>=2 | 50,394 | ❌ 仍有 `今天` `公司` `工作` `同事` 等日常词 |
| 打分表 | 4,693 | ⚠️ 能，但只覆盖组合短语，裸词会漏 |

实测负样本（完全无害的句子）：

| 用法 | 正样本命中 | 负样本误报 |
|---|---|---|
| trie 全部（raw） | 67 | **6/6 句误报** |
| trie 长度>=2 | 35 | **6/6 句误报** |
| 只用打分表 | 6 | **0/6 误报** ✅ |
| `SearchWord` + `out>=0` | 见下 | 见下 |

**`FalunWord.lib` 本质是通用词库，敏感词只是其中一部分。**
真正区分好坏的是**打分表**（`out >= 0`）。

## 7. 诚实边界

- `out == -1` 的词（`法轮功`、`明慧网`）**为什么没有分数**，不清楚。
  可能是分数记在父/子节点上，也可能这些词靠别的规则判定。
  实测它们在 trie 里存在，但 `+12` 是 `0xFFFFFFFF`。
- 反动度 / 红黑度的**数值语义**仍无公开文档（`attested=False`）。
- 组合短语 vs 原子词的**优先顺序**（长匹配优先还是分数优先）还没验证。
