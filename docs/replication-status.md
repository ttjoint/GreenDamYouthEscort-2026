# 复刻成熟度盘点：哪些能复刻，哪些不能

**先说结论：不能说「原引擎的 HNC 表现已经可以复刻了」。**

准确的说法是：

| 能力 | 状态 | 依据 |
|---|---|---|
| **词条过滤**（找敏感词 + 打分） | ✅ **完全能复刻** | 4,693 条打分表全部导出，`SearchWord` 往返 99.8% |
| **句类分析**（HNC 核心） | ❌ **完全不能** | 12 个 `.lib` 一个都没有，`Ini` 第一步就失败 |
| **语义网络 / 五元组** | ❌ 不能 | 同上 |
| **句蜕 / 块扩 / 团块排除** | ❌ 不能 | 只能拿到输出格式字符串，拿不到逻辑 |

过滤只是 HNC 的**外围功能**，不是 HNC 本体。把它当成「HNC 复刻完成」
是把外壳当成了核。

## 1. 过滤这块：能复刻，但价值要打折

### 已验证的部分

```
FalunWord.lib
  ├─ trie 272,920 节点        通用词库（今天/公司/工作 都在里面）
  └─ 打分表 4,693 条          每条 (反动度 0-7, 红黑度 0-4)
```

`SearchWord`（0x2550）第 4 个参数 `int&` 返回打分表下标：

- `out >= 0`：命中，值即下标
- `out == -1`：trie 里有，无分数
- `out == -2`：trie 里没有

往返校验 4,683 / 4,693 = **99.8%**。

### 但这份打分表不是通用规则

最近一次检查发现的事实：

```
条目形态：plain 4406 条，带引号/括号修饰 287 条

'法轮功'  在表里（idx=16，得分 (0,1)）
 法轮功   不在表里（SearchWord 返回 -1）

法轮功 共有 3 种带修饰写法：
  '法轮功'
  "法轮功"弟子
  [法轮功]
```

**说明**：4,693 条是**某份具体文档的原文片段**，
不是「把敏感词规范化后登记」的词表。裸词 `法轮功` 根本没注册。

这带来两个后果：

1. **无法直接当屏蔽词用** —— 词形不规范，`法轮功` 三个字匹配不上。
2. **复刻它意义有限** —— 它记录的是「这篇文章里出现了这些串」，
   不是「这类词该不该拦」。

### 分数语义仍然未知

`反动度 0-7` / `红黑度 0-4` 具体怎么映射到「拦截 / 放行」，没有公开文档。
我连 `Handler.dll` 里的调用方都还没看。`attested=False`。

## 2. HNC 本体：不能复刻

### 硬阻断（反汇编确认，12 个检查点）

```
CSentenceObj::Ini
  ├─ Word.lib              ❌
  ├─ SentLib.lib           ❌
  ├─ 句类表                ❌
  ├─ ActiveMode.lib        ❌
  ├─ DefIndex/Defl0*.lib   ❌
  ├─ UnifyPerc.lib         ❌
  ├─ EgPerc.lib            ❌
  ├─ 多动词框架            ❌
  ├─ ASCII 表              ❌
  ├─ 句结构表              ❌
  ├─ JiBenJL.lib           ❌
  └─ rule.lib              ❌
```

分发包里只有 `FalunWord.lib`。`Ini` 走到第一个检查点就打印
`WordLib Ini Err!` 并返回。没有这些文件，`GetSentenceALC` 永远返回 7。

### 已经拿到的（但只是骨架）

| 拿到 | 怎么拿的 | 够不够复刻 |
|---|---|---|
| 输出 XML 格式（`<主句>`/`<块扩>`/`<句蜕>`…） | `.rdata` 字符串 | 只是格式 |
| 21 个源文件名 | 调试字符串 | 只是文件名 |
| 72 个导出函数名 | 导出表 | 没有实现 |
| 24 句类码 | 早前逆向 `0x30650-0x30AF0` | 部分 |
| `MakeALC` 返回码 | 反汇编 | 只是控制流 |

**没有任何一个 `.lib` 的格式被完整解开，也没有任何一份语料对照表。**

## 3. 我们自己重写的那套在哪

项目里的 `chunker.py` / `l_concepts.py` / `similarity.py` 是
**按论文重建的**，不是复刻引擎：

| 模块 | 依据 | 验证状态 |
|---|---|---|
| `chunk_tags.py` | 论文附表（78 个介词） | 数字锚点测试 |
| `l_concepts.py` | 论文 11.1 l 准则 | 数字锚点测试 |
| `chunker.py` | 论文 11.2 切分策略 | **真实语料上 66.7% 退化为单块** |
| `similarity.py` | [王] 论文 1/3/4/5/6 式 | 替代实现，`degraded=True` |

**`chunker.py` 在真实语料上是失败的**（`docs/corpus-eval.md`）：
有效分句退化率 66.7%，其中 99.8% 因为「无谓语候选」。
动词表 208 条只覆盖真实双字 token 的 2.47%。

所以「HNC 复刻」这条路，连我们自己重建的版本都还没跑通。

## 4. 诚实的差距清单

按「离可用有多远」排序：

1. **`Word.lib`**：没有它切词都做不了。可以从 `FalunWord.lib` 的 trie
   反推一份词表，但**没有词性/词义**，HNC 要的正是这个。
2. **句类判定表**（24 类怎么判）：论文有 A/B/C/D/E/J/K 的定义，
   但具体到「这句话是 DJ 还是 D1」没有对照表。
3. **辅块 7 类**（Ms/In/Wy/Cn/Re/Pr/Rt）：论文有定义，判定规则不完整。
4. **句蜕 / 块扩 的识别**：只有输出标签，没有判定逻辑。
5. **`!31116 ↔ X22/XR011` 映射**：完全空白。

## 5. 所以现在该怎么定位

**不要**说「HNC 复刻完成」。准确表述：

- 我们**能复刻原引擎的词条过滤**（含打分表），这是外围功能，
  且这份打分表本身不规范、不可直接复用。
- 我们**不能复刻 HNC 的句类分析**，缺 12 个数据文件，且没有公开格式。
- 我们自己按论文重建的 chunker **尚未在真实语料上跑通**。

如果目标是「让绿坝这类产品的屏蔽效果变好」，那么：

- 原引擎的**过滤架构**（两层 trie + 打分）值得学 —— 已摸清。
- 原引擎的**具体词表**不值得抄 —— 不规范、不可复用。
- HNC 的**句类分析**帮不上忙 —— 连原厂都没把它用在这上面
  （`Handler.dll` 的过滤走的是 `CFWordLib`，不走 `CSentenceObj`）。

## 6. 下一步建议（按性价比）

| 优先级 | 做什么 | 理由 |
|---|---|---|
| 高 | 把 `chunker.py` 的退化率从 66.7% 降下来 | 这是唯一真正在用的模块 |
| 高 | 用体标记（着/了/过）自动抽候选动词 | 动词表 2.47% 覆盖率是根本瓶颈 |
| 中 | 查 `Handler.dll` 里 `GetWordFanDong` 的调用方 | 才知道分数怎么映射成拦截 |
| 低 | 继续找那 12 个 `.lib` | 网上已确认绝迹 |
| 低 | 反汇编 `CheckVV` / `CheckRelNigRule` | 过滤 API 的补充 |

**不建议**继续在「还原引擎」上投入 —— 数据文件绝迹这条路已经走到头了。
