## 二、分块器在真实语料上的退化（核心问题）

### 2.1 退化率

只统计纯汉字、长度 ≥4 的分句（排除引号残片和标点碎片）：

| 语料 | 有效分句 | 单块退化 | 比例 |
|---|---|---|---|
| 普通小说 | 11,329 | 7,061 | 62.3% |
| 成人语料 | 8,908 | 6,445 | 72.4% |
| **合计** | **20,237** | **13,506** | **66.7%** |

### 2.2 退化的具体原因

`tools/diagnose_chunker.py` 的归因：

```
[普通小说] 分句 18,889，单块退化 12,146 (64.3%)
  其中「有谓语候选」 25 (0.2%)
  其中「无谓语候选」 12,121 (99.8%)   ← 全部卡在这里
```

退化样本：

```
看着这个行星上存在了五千年的文明      verbs=[]   ← “看着”“存在”都没认出
它曾经历过比这大得多的巨变          verbs=[]   ← “经历”没认出
他们不想惹麻烦                 verbs=[]   ← “不想”没认出
被毛毛虫国吞并                  verbs=[]   ← “吞并”没认出
那个地球表面可以看得更细了            verbs=[]   ← “看得”没认出
```

这些句子**都有谓语**，问题在于动词表没收录。

### 2.3 覆盖率测量

```
语料双字 token 103,615（唯一 35,191）
动词表 208 条，覆盖 token 2,563 = 2.47%
```

**动词表覆盖真实文本的 2.47%。** 这是 66.7% 退化的直接原因。

### 2.4 上界实验：把覆盖率补上去能到多少

把语料高频 top-3000 双字全塞进动词表（**这是作弊上界**，其中大半
是名词，会引入大量误切）：

```
动词表 208 → 3,117 后：单块率 62.3% → 4.5%
```

结论：**瓶颈是词汇覆盖率，不是分块逻辑。** 补词汇能立刻解决绝大部分
退化，但必须是有原则地补，不能拿高频词表硬塞。

### 2.5 为什么这对本项目是坏消息

`docs/hnc-theory.md` 里记录的边界是"`SENTEN.LIB`/`JiBenJL.lib` 未分发"。
现在测出来一个更基础的问题：**连词语级的 v 概念标注都没有**。

HNC 理论要求用概念类别符号（`v`/`g`/`u`/`z`/`r` 五元组）标注每个
词，而这份标注就在缺失的 `JiBenJL.lib` 里。没有它，`_find_verbs_safe`
只能靠手写词表，而手写 208 条覆盖 2.47%，手写 3000 条也只能
覆盖到"高频"这一层，且必然混入名词。

**这不是调参能解决的，是数据缺失。**

## 三、HNC 结构特征能否用于屏蔽

### 3.1 语料整体均值（`bench_corpus.py`）

| 特征 | 小说 | 成人 | 相对差 |
|---|---|---|---|
| aux_ratio | 0.1241 | 0.1057 | -14.9% |
| e_ratio | 0.1174 | 0.1019 | -13.2% |
| jk_per_e | 6.4614 | 7.7775 | +20.4% |
| ms_ratio | 0.0533 | 0.0562 | +5.5% |
| pr_ratio | 0.0423 | 0.0479 | +13.2% |
| cn_ratio | 0.7442 | 0.7360 | -1.1% |
| blk_len | 7.1077 | 6.6677 | -6.2% |
| chk_per_sent | 4.7953 | 4.6313 | -3.4% |

看似有差异，但——

### 3.2 单文件判别力（`bench_discriminate.py`）

```
特征                   AUC       最优阈值      上限准确率      留一法
aux_ratio          0.309     0.0000     90.64%   90.64% （方向反转）
e_ratio            0.284     0.0000     90.81%   90.81% （方向反转）
jk_per_e           0.753     1.0000     90.81%   90.81%
ms_ratio           0.589     0.0000     89.84%   89.84%
pr_ratio           0.562     0.0000     88.43%   88.43%
cn_ratio           0.403     0.0000     90.55%   90.55% （方向反转）
blk_len            0.445     4.5082     90.81%   90.81% （方向反转）
chk_per_sent       0.514     1.0000     90.72%   90.72%

基准：全判「成人」的准确率 = 90.90%
```

**没有任何一个特征的准确率超过 90.90% 的基准。** 而且最优阈值普遍
退化为 0——意思是"只要块数 > 0 就判成人"，等价于全判成人。

`jk_per_e` 的 AUC 0.753 是唯一像样的信号，但它的最优阈值是 1.0
（即"只要 JK/E > 1 就判成人"），准确率仍低于基准。

**结论：单文件聚合的结构特征没有判别力。** 文件级平均把信号抹平了。

## 四、现有 FalunWord 词表用于色情屏蔽的效果

### 4.1 它确实是领域外的

```
novel  文件   103   3,883,731 字
       等级>0 命中   99 文件 (96.12%)  等级分布 {1:4, 3:6, 4:9, 6:4, 7:76}
adult  文件  1029  43,754,754 字
       等级>0 命中 1001 文件 (97.28%)  等级分布 {1:81, 3:134, 4:52, 5:27, 6:42, 7:665}
```

**普通小说 96.12%，成人语料 97.28%**——几乎没有区别。这份词表
针对的是法轮功相关内容，与色情无关。用它做色情过滤等于随机拦截。

### 4.2 顺带发现的一个 `semantic.py` 语义陷阱

`Verdict.hits` 会把**任何**匹配到的词条记进去，包括等级 0 的普通词。
普通小说里命中最多的：

```
'执政' 218  (等级 0)
'时间' 189  (等级 1)
'巨大' 105  (等级 0)
'社会'  74  (等级 0)
'基地'  68  (等级 3)   ← 这个会触发拦截
```

`hits` 的长度**不能**当命中数用。有效指标是 `max_level > 0`。
用 `hits` 会得出"普通小说比色情小说更敏感"的荒谬结论。

这个陷阱已写进 `tools/bench_corpus.py` 的文档串。

## 五、诚实结论

### 做成的

1. 三套可复现的评测工具，能跑全量 47M 字语料。
2. 定量定位了分块器的真实瓶颈（词汇覆盖率 2.47%）。
3. 定量否证了"结构特征可直接做屏蔽判据"这个假设。
4. 定量否证了"FalunWord 词表可用于色情过滤"。

### 没做成的

1. **分块器在主任务上只有 33% 的分句能产出结构**。之前测试里 134
   项全绿，是因为测试用例都是我按规则挑的规整短句。真实语料一测
   就露底。这是一次有价值的自我否证。

2. **HNC 结构层对屏蔽系统当前零贡献**。它的理论价值（句类判定、
   语义块角色）依赖概念标注数据，而那份数据未分发。

### 下一步的三个选项

**A. 补词汇（工程向，收益立刻可见）**
用带体标记（着/了/过）的语料自动抽取候选动词，人工或半自动筛选后
扩充 `DEFAULT_VERBS`。预期单块率从 62% 降到 30% 以下。代价：仍然是
词表，不是 HNC 的概念标注；标注工作量随覆盖率线性增长。

**B. 承认边界，转做能做的部分（诚实向）**
放弃用 chunker 做屏蔽判据，回到 `semantic.py` 这类字面词表 +
正则的路线，把 HNC 部分当作**解释性**组件而非**判定性**组件。

**C. 补 HNC 数据（理论向）**
继续找 `JiBenJL.lib` / `SENTEN.LIB`，或从已分发的二进制里反向恢复
概念类别表。这是唯一能让 HNC 层真正工作的路径，但成功率不可控。

我的建议是 **A + B**：先用 A 把覆盖率做上去（这是当前性价比最高的
动作，且不依赖任何缺失数据），同时按 B 调整架构定位——屏蔽判定
交给词表层，HNC 层负责给出"为什么"的结构化解释。

## 更正：分句退化率长期被算错了

上面引用的「单块退化 66.7%」以及后来 `docs/verb-table.md` 里的
「54.3% / 66.9%」，**口径是错的**。数字本身是真测出来的，但它衡量的
不是它声称衡量的东西。

### 错误一：`diagnose_chunker.py` 没走真实分句器

旧代码自己切分句：

```python
for clause in re.split(r"[，。！？；\n、]+", text):
```

这绕过了 `_split_clauses()` 的引号保护和碎片吸收，所以它测的是一个
**库里根本不存在的分句器**。改成 `_split_clauses()` 之后分句数从
18,889 降到 9,878（同一批 10 个文件）——差了将近一倍。

### 错误二：分句加权本身就是误导指标

按分句数算，一个 2 字的 `此刻` 和一个 100 字的完整句**等权**。
实测这两个群体的退化率差两个数量级：

| 口径 | 退化率 |
|---|---|
| 分句加权 | **46.1%** |
| 字符加权 | **18.9%** |

| 群体 | 平均长度 |
|---|---|
| 退化的分句 | **8.1 字** |
| 切开的的分句 | **172.1 字** |

结论：**长句几乎都切得开，退化的全是短碎片。** 分句加权被
`此刻` / `就在这时` / `说道` / `王林目光一闪` 这类东西淹没，
而这些本来就不是句子。

只保留「像句子」的（含 ≥2 个汉字且汉字占比 ≥50%）之后：

| 口径 | 退化率 |
|---|---|
| 分句加权 | 43.8% |
| 字符加权 | **17.9%** |

### 现在的数字

| 语料 | 分句加权 | 字符加权 |
|---|---|---|
| 普通小说 | 40.8% | **18.9%** |
| 成人语料 | 52.5% | 未单独测 |

`diagnose_chunker.py` 现在两个都打，并标注字符加权是实际影响口径。

### 另外修掉的 13,000 个碎片

实测退化碎片里有三类不该独立成句的东西，已在分句层吸收
（`_TIME_ADVERBS` / `_SAY_VERBS` / `_is_attach_fragment`）：

| 类别 | 次数 | 例 |
|---|---|---|
| 时间/情状状语 | 10,139（4.2%） | `此刻` 605、`就在这时` 488、`顿时` 435 |
| 对白提示语 | 3,940（1.6%） | `说道` 1498、`缓缓说道` 312、`道` 240 |
| 连词副词 | （原有 `_LEADING_ATTACH`） | `但`、`于是`、`而且` |

这三类在论文里都是**辅块内容**（K(jm) 时间/条件类、方式类），
不是独立句子。分句层在它们后面断开本来就是错的。

### 教训

评测指标要和它声称衡量的东西对齐。一个把 `此刻` 和完整长句等权
的指标，会把「碎片多」误报成「分析能力差」，进而让人去补动词表
——补了也没用，因为那些碎片压根不是句子。
