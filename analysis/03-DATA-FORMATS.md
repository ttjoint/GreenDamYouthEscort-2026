### 布局（六段 `fread`，来自 `CFWordLib::LoadLib` @ `0x100022D0`）

```
+0                     u32  n1 = 272,920         链节点数
+4                     n1 × 16 B                 链节点数组
+4+n1*16               u32  (固定暂存表)
...                    0xFFFF × 16 B            固定暂存表
                       u32  n2 = 4,693           词义记录数
                       n2 × 16 B                 词义记录数组
                       u32  n3 = 36,943          字符池字数
                       n3 × 2  B                 UTF-16 字符池
末尾 5 B               "HNCIT"
```

### 闭合算术（决定性）

```
4 + 272920*16 + 65535*16 + 4 + 4693*16 + 4 + 36943*2  =  5,564,266
5,564,271 − 5,564,266                                  =          5  == len("HNCIT")
```

实测文件末 5 字节 = `b'HNCIT'`。**零剩余、零猜测。**

### 链节点 16 字节结构

| 偏移 | 字段 | 含义 |
|---|---|---|
| `+0x00` | `code` | Unicode 码位 |
| `+0x04` | `next` | **同一词条内**下一字符的索引，0 = 结束 |
| `+0x08` | `children` | 分支续接数，0 = 叶 |
| `+0x0C` | `sense_id` | 词义表下标，或 `0xFFFFFFFE`/`0xFFFFFFFF` |

`next` 是**字符路径**而非兄弟链 —— 这是旧文档两次失败的根源。

### ⚠️ 已推翻的旧布局

`RE/README.md` #49 的「16 字节定长记录 + 哨兵 `0xFFFFFFFE` 出现 171,883 次」：
按该文档自己给的 16 字节步长、哨兵位于 `+8` 扫描，命中 **0** 次。
→ `REFUTED`（见 `07-CONFLICTS.md` K-05）

**关键校正（推翻 RE#67）**：`17.允许自动关机` **在 `XNet2.exe` 中不存在**。

### `sys.dat` 67 dword 实测值

非零下标（0 基）：`3,4,5,7,8,13,14,16,17,18,20,21,22,24` —— 共 14 个，范围 3–24。

> **校正 RE#33**：RE 称「索引 3–22 有值、23–66 全零」。
> 实测 **24 亦非零**（值 1），故应为「3–24 区间有非零，25–66 全零」。
> 边界描述小偏，已记入 `08-CLAIMS-DEMOTED`。

### 下标映射（`CLOSED` —— 已由 XNet2 代码证实）

**证据**：`probe/p15_sysdat_flow.txt`。

`XNet2.exe` `0x40bbd0`（系统预设级别6 初始化分支）：

```
0x40bbb8  mov ebp, 1
0x40bbf5  mov [esp+0x50], eax   ; eax=2
0x40bc01  mov eax, 0xe          ; 14
0x40bc0d  mov ecx, 0x43         ; 67 dword
0x40bc12  lea esi, [esp+0x40]   ; 栈临时数组起点 = 索引 0
0x40bc16  mov edi, 0x46f1e0     ; 全局策略数组
然后 rep movsd 拷 67 dword
```

数组下标换算 `索引 = (栈偏移 − 0x40) / 4`：

| 栈偏移 | 索引 | 策略 | 预设值 | 语义 |
|---|---|---|---|---|
| +0x50 | 4 | 5 图像过滤级别 | 2 | 中 ✓ |
| +0x54 | 5 | 6 图像过滤自动加黑名单 | 1 | 启用 ✓ |
| +0x5c | 7 | 8 禁止程序上网(端口) | 1 | 启用 ✓ |
| +0x60 | 8 | 9 禁止程序上网(进程) | 1 | 启用 ✓ |
| +0x6c | 11 | 12 系统预设级别 | 2 | ✓ |
| +0x88 | 18 | 19 抓屏数据保留时间 | 14 | 天 ✓ |

**裁决**：`下标 = 策略号 − 1` 映射**成立**（代码直接证据，非推理）。

### `sys.dat` 数据流（`CLOSED`，见 `p15_sysdat_flow.txt`）

```
XNet2 全局策略数组 @0x46f1e0 (67 dword)
  → SG_Control(0x262, 268, &array) 命令码 610
  → SurfGd 内部全局 @0x10228008（EnterCriticalSection + rep movsd 67 dword）
  → 返回后 WriteFileBin("xconfigs.dat", 268 B, "wb")
```

- `sys.dat` / `xconfigs.dat` 内容相同（MD5 相同），是同一策略数组的两个副本。
- `sys.dat` 是安装模板（无 PE 静态读）；`xconfigs.dat` 是运行时持久化副本。
- `sysEx.dat`（32 B）是 XNet2 写出的（`WriteFileBin` + `"wb"` + 36 字节），非配置读入。

**状态 `CLOSED`**：映射与数据流均已由代码证实。

## F-004 `.dat` 词库编解码（含 `wfile.dat` 等）

| 项 | 值 |
|---|---|
| 文件 | `wfile.dat`, `adwfil.dat`, `adwapp.dat`, `iawfil.dat`, `lgwfil.dat`, `vgamfil.dat`, `TrustUrl.dat` |
| 方法 | `CODEC-RT` |
| 证据 | `tools/decode_wordlist.py`（现成实现，本次实测复验） |
| 状态 | ✅ **CLOSED** |

### 算法

```
密文符号值 v = byte - 0x30        (v ∈ 0..63)
每 2 符号 → 12 bit : V = (v0 << 6) | v1
明文字节位:
  bit0 ← V[0]        bit1 ← V[1]
  bit2 ← !V[2]       bit3 ← !V[3]
  bit4 ← V[6]        bit5 ← V[7]
  bit6 ← !V[8]       bit7 ← !V[9]
  V[4],V[5],V[10],V[11] = 填充
行分隔 "\\r\\n" 原样保留；文本编码 GBK
```

### 本次实测

```
wfile.dat (260 B) → 135 B GBK：
  1 成人/色情网站 adwfil.dat
  1 成人/色情网站(严格) adwapp.dat
  1 暴力游戏 vgamfil.dat
  1 同性恋 lgwfil.dat
  1 非法活动/毒品 iawfil.dat

往返测试 5/5 通过（含中文字节、0x01–0x27 全字节序列）
```

**结论**：确实只是**可逆混淆**，无密钥、无随机化。`CLOSED`。
`wfile.dat` 是**分类索引**（类别号 + 中文名 + 词库文件名），非词表本体。

### 本轮取得的确凿事实（`probe/p12_urf_consumer.txt` + `p13_urf_header.txt`）

1. **消费方 = `appface.dll`（AppFace 皮肤库），不是 `SurfGd.dll`。**
   证据：`gn.exe` 里 `%s\%d.urf` 格式串 → `call [esi+0xc8]` 皮肤加载函数，
   且 `gn.exe` 从 `AppFace.dll` 只导入 `ord3 = SkinWindowSet`。
   → **旧文档「Surfgd.dll 解析 .urf」与「解析器不在静态文件里」两次判定均被推翻。**
   → 旧文档「AppFace 皮肤包」方向**对**（实锤）。

2. **`appface.dll` 是 UPX 加壳（全树唯一）**：`UPX! @0x3e0`，段 `UPX0(RawSize=0)+UPX1+.rsrc`，
   导出全指向 UPX0 空区。**这就是 .urf 之谜十轮纠缠的根因**：
   唯一加壳模块恰是它的消费方，静态反汇编只见 `00 00`。

3. **UPX 脱壳已成功**（Unicorn 模拟 stub 执行）：UPX0（`0x10001000`–`0x1006f000`）已解压，
   解压后是正常 MSVC C++ 代码。卡在 IAT 修复阶段（需真实 Windows API）。
   脱壳产物：`/tmp/appface_upx0.bin`（450,560 字节）。

4. **`.urf` 文件头精确结构（修正早前「6 字节魔数」误记）**：
   - 前 **10 字节共同前缀** = `a1 a0 ae ab bc a8 aa a8 a0 a8`
   - `0x0c-0x0d` = `25 9b`（固定）
   - `0x13-0x2e` = 28 字节固定块
   - 头 10 字节最高位全为 1（都可能 ≥0x80）
   - **熵 7.962 来自内嵌 GIF 的 LZW 压缩数据，不是加密**（见下 5）

5. **`.urf` 是明文容器，不是加密文件**（重大认知修正）
   - `1.urf` 内 `0x6ccb`、`0x7a15` 两处是**明文 `GIF89a`** 图片资源（未加密）
   - `_urf_images/` 目录里旧文档提取的 12 张 GIF 全部真实且可复现
     （独立验证 6 个偏移全部是 GIF 头）
   - 元数据区（头→第一个 GIF）含 279 个 `0xa8` 分隔符，是二进制结构
   - **高熵 = GIF LZW 压缩数据的高熵，≠ 加密**
