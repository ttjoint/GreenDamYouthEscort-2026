## 核心结论（C-001…C-020 摘要）

逆向工作分多轮完成，每轮都有字节级证据，纠正了旧文档（`REVERSE-ENGINEERING/`）
的多处错误。关键结论：

1. **`.urf` = AppFace 皮肤包**（明文 GIF 容器，非加密），消费方 `appface.dll`（UPX 壳）
2. **`FalunWord.lib`** = 六段 `fread` 布局（算术闭合，残差 = 5 = len("HNCIT")）
3. **过滤体系** = 双向五层（进程 → IP/端口 → 协议指纹 → URL → 关键词）
4. **名单（四组）**：A=出站URL(100)、B=监控进程(无显式上限)、C=入站关键词(1000)、D=动态(1500)
5. **规则语法**：`{词A,词B}[字C,字D]` = （含A或B）且（含C或D）
6. **控制协议**：`SG_Control` 命令码（55 个实现），策略/名单下发中枢
7. **HNC 句法子链**：代码完整但入口零调用（产品只用词条级 `CorpGroup→MakeALC`）

详见 `09-SPEC.md`（复刻契约）与 `00-MASTER.md`（完整结论）。

## 关于 probe 脚本

- probe 脚本是**证据生成器**，其输出（.txt/.tsv）已保存在本目录。
- 脚本用 `os.path` 相对定位**原始安装树**（`LH-installed-tree/`），
  该树被 `.gitignore` 排除（版权原因），不在此仓库内。
- **重跑条件**：需在包含 `LH-installed-tree/` 的上级目录运行（原始工作目录），
  或在脚本中调整 `ROOT` 路径指向原始安装树。

## 方法论（反幻觉纪律）

- 每个事实必须可重跑验证（`probe/` 脚本）
- `CLOSED` 只授予独立取证的事实；`DOC-CLAIM` 计零
- `REFUTED` 不删除（防止重新推导出同样的错误）
- 已知核验器误差（§1.4 主账）：大小写、VA vs 文件偏移、显示截断、编码层

## P26（M4 轮廓路径查证）

`probe/p26_image_checkex.txt` / `p26_image_checkex.py`

起因：`IMG07` 的证据只到导入表层面，「导入了」不等于「调用了」。

结论：
- 17 个 OpenCV 函数**全部有真实调用**，无死导入
- `CImage.dll` 有 **17 个** `CHECK*` 导出，账本此前只记 `CHECKEX2`
- **15 个** `CHECK*` 函数 3 层内可达 OpenCV 桩
- 主判定在 `CHECKEX8x`(845 指令) / `CHECKEX13x`(1363) / `CAPSCREEN`(1353)，
  **语义未逆向**

影响：M4 只复刻了两个辅助判据（宽高比、高亮度），**主判定路径未复刻**。
`docs/image-layer.md` §5.2 已补上这一点，并更正了早期「未找到调用路径」的错误说法。

## P27（M4 主判定逆向）

`probe/p27_checkex13x.txt` / `p27_checkex13x.py`

**这是图像判定最重要的文件。** 若只读一份图像相关探针，读这个。

还原了 `CHECKEX13x` 主判定 `0x100078e0` 的完整逻辑：

- 门控：宽高 ≥ 32，**整数**长宽比 ≤ 8
- 灰度：0.11/0.30/0.59 + 0.5（BGR 序）
- 中心 8×8 窗口**总体**标准差，阈值 1.4
- 8 档纹理分级（20/40/75/155/190/270/295/316），级 0/1/3/6 权重为 0
- 结果按 `9*g1+3*g2+g3` 打包（0–71）

**推翻了 p22 的一条合并表述**：`CHECKEX13x` 路径不调用
`cvFindContours`/`cvCanny`/`cvHoughLines2`——那些在别的 `CHECKEX*` 里。
「Haar + 肤色 + 轮廓」不是一套组合，是不同函数的不同算法。

实现：`src/green_dam/imaging_checkex.py`，41 项测试。

## P28（`CHECKEX8x` 逆向，含肤色检测）

`probe/p28_checkex8x.txt` / `p28_checkex8x.py`

**这条推翻了「没有肤色检测」的印象。** 读图像相关文档前必读。

- 门槛 160、缩放宽 160、特殊门控（宽==160 且 宽/高>20 → 返回 10）
- ratio 阈值 0.08 / 0.15 / 0.6 —— 与 `CHECKEX13x` 的 0.008/0.4 **完全不同**
- **真肤色检测** `0x100096c0`：`R>G>B` + 饱和度 > 0.09 + 10 个保留色相桶
  `{2,4,5,7,8,11,13,14,16,17}`，用 **HSV** 而非直方图
- 矩形分析 `0x10006ee6`（0.54/252）**未逆向，明确不复刻**（代码里抛异常）

### 一条方法论教训

p22 后期发现 `0x10008e70` 不是肤色检测，就下了「产品没有肤色检测」的结论。
**但肤色检测在另一个函数里，用的是完全不同的方法。**

> 从「某个函数不是 X」推不出「产品没有 X」。

这条教训写进了 `00b-FACTS.md` 的 IMG32 与 `docs/image-layer.md`。
