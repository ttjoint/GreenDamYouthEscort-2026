# 名单 B 语义确认（P6 成果）

## 结论：名单 B = 监控目标进程名单

完整证据链（全部反汇编实测）：

### 1. 设置方（XNet2 下发）
- XNet2 0x1f6a3：`SG_Control(0x1bb, 0x3840=14400=100×144, buf)`
- 遍历 100 条 144 字节记录，逐条下发

### 2. 存储方（SurfGd 接收）
- 名单 B 基址 0x102186d8（记录数据）+ 计数 0x10228124
- 每条 144 字节，首字段字符串

### 3. 匹配方（0x10003499：进程遍历匹配）
```
0x10003499:  ; 被 DBFP_Socket @0x54b6 调用
  清零结果数组 0x10218548（100×4B）+ 计数器 0x10060e00
  call 0x10009960(0xf,0)   ; CreateToolhelp32Snapshot
  call 0x1000995a          ; Process32First/Next 遍历
  对每个进程:
    0x10014076 小写化进程名
    遍历名单B(0x102186dc, 100条):
      0x1000a8a0 strstr 匹配
      命中 → 记录 PID 到 0x10218548[计数]
```

### 4. 判定方（0x10003340：当前进程是否命中）
```
0x10003340(pid):
  遍历 0x10218548（100 槽）
  槽值 == pid → 返回 1（命中）
  否则返回 0
```

### 5. 使用方（DBFP_Socket @0x54b6-0x54d1）
```
0x54b6  call 0x10003499        ; 遍历进程，构建命中结果
0x54bb  call [0x1022004c]      ; GetCurrentProcessId
0x54c2  call 0x10003340        ; 当前进程在名单B中？
0x54cf  test eax,eax
0x54d1  je  0x1000554c         ; 不在 → 跳过URL过滤
... 在名单B中 → 继续 URL/域名过滤
```

## 语义确认

**名单 B = 监控目标进程名单**（产品要过滤其网络行为的程序列表）。

- 与 `kwselectinfopp.dll`（8 个监控目标：QQ/msnmsgr/thunder 等）呼应：
  那是静态初始名单，名单 B 是运行时从 XNet2 下发的完整进程名单。
- 进程名在名单 B 中 → 该进程的网络行为被进一步过滤（URL/域名/内容）。

## 三名单最终语义（全部确认）

| 名单 | 基址 | 语义 | 使用方 |
|---|---|---|---|
| A | 0x1021bf18 | 出站 URL/协议指纹 | DBFP_Send (0x10002006) |
| B | 0x102186d8 | **监控目标进程名单** | DBFP_Socket (0x10003499) |
| C | 0x1003db84 | 入站关键词黑名单 | DBFP_Recv (0x10001dcb) |

## 附：结果数组与计数器

| 地址 | 内容 |
|---|---|
| 0x10218548 | 命中进程 PID 数组（100×4B） |
| 0x10060e00 | 命中计数 |
