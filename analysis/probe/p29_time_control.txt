## 0. 功能语义（来自手册图 18/19 + 二进制）

时间控制是一个 **7 天 × 24 小时的允许/拒绝网格**：

```
        D/H  上午              下午
             12 1 2 3 ... 11 12 1 2 3 ... 11
  星期日   [ ][ ][ ]...        [ ][ ]...
  星期一   [ ][ ][ ]...
  ...
  星期六   [ ][ ][ ]...
```

| 元素 | 语义 |
|---|---|
| 行 = 星期日..星期六（7 行） | 一周每天 |
| 列 = 24 小时（上午 12,1..11 / 下午 12,1..11） | 一天每小时 |
| 单元格灰色 | 该小时**不允许**上网 |
| 单元格绿色（图例「允许」） | 该小时**允许**上网 |
| 图 18 | 默认全灰、`允许上网时间控制` 未勾选 |
| 图 19 | 星期三 3 个格子绿色、复选框勾选 |

网格下方三个设置项：

| UI 文本 | 语义 | 对应 |
|---|---|---|
| `允许上网时间控制` | 总开关 | **sys.dat 槽 24**（名称表 `0x68dcb` 实测） |
| `自动时间同步间隔（秒）` = 10 | NTP 刷新间隔 | UI 槽 1203 |
| `切换提前5分钟预警` | 时段切换前 5 分钟提示 | UI 复选框 |

## 1. 二进制证据

### 1.1 策略名表（`XNet2.exe`，倒序 GBK 表）

```
0x00068dcb: 允许上网时间控制      ← 槽 24 的名称
0x00068e13: 自动更新时间          ← 槽 21（是"自动更新的时刻"，不是时段）
0x00068e43: 自动抓屏间隔
```

**校正**：早期把槽 21 当成"时间段数据"的候选。实测槽 21 名称是
`自动更新时间`——它是**自动更新的时刻**，与上网时间控制无关。
时间控制的数据**不在 sys.dat 里**。

### 1.2 网格表头字符串（紧跟 `AllowTime` 之后）

```
0x000681bc: "AllowTime"
0x000681c8: 下午
0x000681ce: 上午
0x000681dc..0x000681fa: 星期六,星期五,星期四,星期三,星期二,星期一,星期日
```

这些是时间控制对话框的**网格表头**，与手册截图完全对应。

### 1.3 NTP 服务器（`AllowTime` 之后的 10 个 IP）

```
68.216.79.113, 64.236.96.53, 206.246.118.250, 64.125.78.85, 69.25.96.13,
192.43.244.18, 128.138.140.44, 132.163.4.103, 132.163.4.102, 132.163.4.101
```

全是公共 NTP 服务器。配合 UI 的「自动时间同步间隔（秒）」：
**原厂用 NTP 对时来防止用户改系统时间绕过时段限制**。这是时间控制功能
对抗性的核心——只校验本地时钟的产品，改时钟即绕过。

### 1.4 UI 字符串（`xnet2_lang.ini`，GBK）

```
AllowTime0_1045=上网时间控制
AllowTime0_1108=允许上网时间控制
AllowTime0_1131=保存
AllowTime0_-1=-允许
AllowTime0_1203=自动时间同步间隔（秒）
```

## 2. 没有还原的（如实记录）

**168 位网格状态的存储位置未找到。**

| 排除项 | 证据 |
|---|---|
| sys.dat（268 字节） | 非零槽全在 3..24，任何槽都装不下一周的位 |
| 安装树中的数据文件 | 无时间相关文件（`find -iname "*time*"` 空） |
| `AllowTime` 后的 dword | 早先猜测是缓冲区长度 0x7c；GBK 解码显示那是表头字符串，**猜测撤回** |

可能的位置：注册表（`Software\AppDataLow\` 键存在但未展开）、某个未识别文件。
继续追需要动态调试。

**复刻项目的处理**：移植**语义**（7×24 网格 + 总开关 + 切换预警），
存储自定义（JSON/配置），并在文档里写明这是语义移植而非格式还原。

## 3. 复刻设计（由此确定）

| 组件 | 来源 | 复刻方式 |
|---|---|---|
| `WeeklyGrid` | 手册图 18/19 的网格 | 7×24 布尔矩阵 |
| 总开关 | 槽 24 `allow_time_control` | 已有（`sysdat.py`） |
| `at(now)` 查询 | 网格语义 | 返回该小时是否允许 |
| 边界语义 | 单元格=整小时 | 左闭右开 `[start, end)`，无歧义 |
| 切换预警 | `切换提前5分钟预警` | `next_change(now)` + 5 分钟窗口 |
| NTP 对时 | 10 个 IP + 间隔 10 秒 | **不复刻**（需网络；且对 NTP 服务器的选择是 2009 年的） |
| 存储 | 未还原 | 自定义 JSON，`to_blob`/`from_blob` 往返 |

**关键设计决定**：

1. **格子语义 = 左闭右开**。`grid[3][14] = True` 表示星期四 14:00–14:59 允许。
   手册图未明说边界，但 `[start,end)` 是唯一无歧义的解释（相邻格子无缝拼接）。
2. **查询是纯函数**：给 `datetime` 返回布尔，不读系统时钟。时钟由调用方注入，
   测试才可确定性。
3. **未还原的部分不假装**：NTP 对时不做（架构 §M7 诚实边界——管理员本就可
   改时钟；非管理员的"防随手绕过"不依赖它）。
