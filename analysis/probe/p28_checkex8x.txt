# CImage.dll：CHECKEX8x 判定路径逆向（P28）

方法：`DISASM`（capstone）+ `BYTES`（.rdata 常量实测）
探针：`p28_checkex8x.py`（可复现，只读）

> **阅读顺序**：本文 > p27 > p26 > p22。本文覆盖 `CHECKEX8x`，
> p27 覆盖 `CHECKEX13x`，两者是**不同的算法**，不要互相套用。

---

## 0. 与其它探针的关系

| 主题 | 结论 |
|---|---|
| `CHECKEX13x`（p27） | 灰度 + 中心标准差 + 纹理分级，**无肤色** |
| **`CHECKEX8x`（本文）** | **肤色/色相分类 + 轮廓矩形分析** |
| p22 的「Haar + 肤色 + 轮廓」 | **仍然错**：不是一套，是不同 `CHECKEX*` 的不同组合 |

**本文最重要的更正**：p27 与 p22 后期都说「`0x10008e70` 不是肤色检测」——
这一条**仍然成立**（那个函数确实是过曝检测）。但**肤色检测本身是存在的**，
它在 `CHECKEX8x` 路径的 `0x100096c0` 里，用 HSV 而非 RGB 直方图。

之前"没有肤色检测"的印象是错的，来源是只看了 `0x10008e70` 就下结论。

---

## 1. 骨架（@0x10006fb0，2,704 字节）

与 `CHECKEX13x` 同构，但**返回码不同**：

```
0x10006fb0  sub esp, 0x118
0x10006fb7  call 0x1000a021                 ; __chkstk
0x10006fc6  cmp [esp+0x124], 0x7ab7         ; ← 同样的反调试守卫
0x10006fd1  je  0x10006ff8
0x10006fd3  push 0x2710                     ;   Sleep(10000)
0x10006fd8  call dword ptr [0x1000c044]
0x10006fe9  mov eax, 0x64                   ;   返回 100
0x10006ff5  ret 0xc

0x1000700d  call 0x10004ec0                 ; 构造图像对象
0x10007024  mov eax, 0xffffffeb             ; ← 失败返回 -21
0x1000703a  call cvLoadImage                ; 加载
0x10007055  mov eax, 0xffffffec             ; ← 加载失败返回 -20

0x10007064  ecx = 宽
0x10007067  cmp ecx, 0xa0                   ; ← 门槛 160（不是 0x50）
0x10007076  cmp ecx, 0xa0                   ;   高也要 >= 160
0x10007082  fild 宽; fdivr 160.0; fimul 高  ; 等比缩放
0x100070a0  call cvCreateMemStorage
0x100070b1  call cvResize                   ; → 缩到宽 160
```

**若宽高都 > 160**：缩放到宽度 160（高度按比例）。
**否则**：`cvCreateSeq` + `cvCopy` 直接用原图。

两条分支都汇到 `0x10006d40`（主判定）。

### 返回码对照

| 返回 | 含义 |
|---|---|
| `100` (0x64) | 反调试失败（所有 `CHECKEX*` 共用） |
| `-21` (0xffffffeb) | 图像对象构造失败 |
| `-20` (0xffffffec) | 图像加载失败 |
| `10` (0xa) | 见 §2 特殊门控 |
| `3` | 见 §3 矩形分析 |
| `1` / `-1` | 见 §2 三分支 |
| `0` | 门槛不通过 |

## 2. 主判定 @0x10006d40

### 2.1 特殊门控（宽度恰为 160 时）

```
0x10006d6e  cmp esi, 0xa0           ; 宽 == 160 ?
0x10006d7c  jne 0x10006db0
0x10006d81  idiv edi                ; 宽/高
0x10006d83  cmp eax, 0x14           ; > 20 ?
0x10006d86  jle 0x10006db0
0x10006d99  mov eax, 0xa            ; ← 返回 10
```

**宽度恰好 160 且 宽/高 > 20** → 直接返回 `10`。

这是 `CHECKEX8x` 独有的判据，`CHECKEX13x` 没有。因为缩放目标是 160，
所以"缩放后宽度仍是 160"意味着原图本来就窄——这个分支处理极端长条图。

### 2.2 通用门控（与 `CHECKEX13x` 相同）

```
0x10006db0  cmp edi, 0x20           ; 宽 >= 32
0x10006db9  cmp esi, 0x20           ; 高 >= 32
0x10006dc5  idiv esi; cmp eax, 8    ; 整数比例 <= 8
0x10006dd3  idiv edi; cmp eax, 8
0x10006ddf  call 0x10005150         ; 高亮度早退
0x10006de9  jne 0x10006f8a          ;   命中 → 返回 0
```

### 2.3 双比值三分支

```
0x10006e04  call 0x10003e90         ; 产出两个 double
0x10006e09  fld  [esp+0xc]          ; ratio1
0x10006e0d  fcomp [0x1000d650]      ; 0.08
0x10006e18  jne 0x10006f8a          ; ratio1 <= 0.08 → 返回 0
0x10006e1e  fcomp [0x1000d420]      ; 0.15
0x10006e2d  jne 0x10006e80          ; ratio1 < 0.15 → 走第三分支
0x10006e32  call 0x10001ba0         ; ← 与 CHECKEX13x 同一个函数
```

| 条件 | 动作 |
|---|---|
| `ratio1 <= 0.08` | 返回 `0` |
| `ratio1 >= 0.15` | `0x10001ba0` 非零 → 返回 `-1`；零 → 返回 `1` |
| `ratio1 < 0.15` | 看 `ratio2/ratio1` 与 `0.6`（`0xd550`）比较，同样走 `0x10001ba0` |
| `ratio2/ratio1 >= 0.6` | 同上 |
| 否则 | 见 §3 |

**`0x10001ba0` 在两个 `CHECKEX*` 里都被调用**，语义仍未知（IMG12，OPEN）。

### 2.4 阈值对照（`CHECKEX8x` vs `CHECKEX13x`）

| 常量 | `CHECKEX8x` | `CHECKEX13x` |
|---|---|---|
| ratio1 下界 | **0.08** | 0.008 |
| ratio1 分支点 | **0.15** | 0.4 |
| 缩放宽度 | **160** | （按 `0xd578`） |
| 尺寸门槛 | **160** | 80 |

**两套数值完全不同**——这证实 `CHECKEX*` 不是同一算法的参数化，
而是各自独立的判定变体。

## 3. 矩形/轮廓分析（@0x10006ee6）

最后一段是 `CHECKEX8x` 独有的，`CHECKEX13x` 没有：

```
0x10006eea  eax = 宽 * 高
0x10006ef1  ecx = eax * 3
0x10006ef5  call malloc (序号导入)       ; 分配 w*h*3 字节
0x10006f02  push edi                     ; 缓冲
0x10006f03  ebx = 高/2
0x10006f0f  esi = 宽/2
0x10006f11  push 参数
0x10006f16  call 0x10005250              ; ← 直方图类对象构造
0x10006f1e  eax = 2*(高/2)
0x10006f21  ecx = 2*(宽/2)
0x10006f24  push 0x3fe147ae              ; ┐
0x10006f29  push 0x147ae148              ; ┘ = double 0.54
0x10006f2e  push 0xfc                    ; = 252
0x10006f33  push 0x10010020              ; 数据指针
0x10006f38  push eax                     ; 高
0x10006f39  push ecx                     ; 宽
0x10006f3a  push edi                     ; 缓冲
0x10006f3f  call 0x100094f0              ; ← 阈值分割
0x10006f44  fstp qword ptr [esp+0x1c]    ; 返回 double
0x10006f49  call free (序号导入)
0x10006f52  fcomp [0x1000d518]           ; 1.0
0x10006f75  mov eax, 3                   ; ← 返回 3
```

**`push 0x3fe147ae` + `push 0x147ae148` = double 0.54**。
这是 32 位代码里压 double 常量的标准手法（两半分别 push）。

### `0x100094f0` 是什么

```
0x10009502  edi = 参数3
0x10009508  call 0x100096c0              ; ← 肤色分类（见 §4）
0x1000950d  esi = 宽 * 高 * 8
0x10009516  call malloc                  ; 分配 double 缓冲
0x1000951d  rep stosd                    ; 清零
```

**先调肤色分类，再分配缓冲** —— 所以 `0x100096c0` 是**就地修改**输入图像
（把非肤色像素置黑），不是产生掩码。

## 4. 肤色分类 @0x100096c0（本文最重要的发现）

### 4.1 十个保留的色相桶

```
0x100096d6  [esp+0x40] = 2
0x100096de  [esp+0x44] = 4
0x100096e6  [esp+0x48] = 5
0x100096ee  [esp+0x4c] = 7
0x100096f6  [esp+0x50] = 8
0x100096fe  [esp+0x54] = 0xb  (11)
0x10009706  [esp+0x58] = 0xd  (13)
0x1000970e  [esp+0x5c] = 0xe  (14)
0x10009716  [esp+0x60] = 0x10 (16)
0x1000971e  [esp+0x64] = 0x11 (17)
```

**10 个色相桶，编号 2/4/5/7/8/11/13/14/16/17**（跳过 0/1/3/6/9/10/12/15）。
这些是**被判定为肤色**的色相区间索引。

### 4.2 逐像素处理

```
0x10009746  al = [esi-1]        ; G
0x10009749  cl = [esi]          ; R
0x1000974b  dl = [esi-2]        ; B
0x1000974e  cmp cl, al          ; R > G ?
0x1000975c  jbe 0x100097d0      ;   否则 → 置黑
0x1000975e  cmp al, dl          ; G > B ?
0x10009760  jbe 0x100097d0      ;   否则 → 置黑
```

**前置条件 `R > G > B`** —— 这是皮肤像素的经典 RGB 序关系。
不满足的像素直接被排除（省掉 HSV 转换）。

### 4.3 HSV 转换 @0x10009090

```
0x10009099  读三个参数（R/G/B，各 0..255）
0x100090a1  任一 > 255 → 跳 0x10009356（错误出口）
0x100090d5  求 max（fcom + 条件移动）
0x100090fc  求 min
0x10009115  max == 0.0 ? → 输出全 0（黑色）
```

之后算饱和度与色调，写回调用方提供的三个 double 指针。

### 4.4 判定链

```
0x10009787  fld [esp+0x28]           ; 饱和度
0x1000978b  fcomp [0x1000d530]       ; 0.09
0x10009796  jne 0x100097d0           ; 饱和度 <= 0.09 → 置黑
0x100097b8  call 0x10009360          ; ← 色相分档
0x100097c3  在 10 项表里线性查找
0x100097c5  je  0x100097db           ; 找到 → 保留
0x100097d0  mov byte [esi-2], 0      ; ┐
0x100097d4  mov byte [esi-1], 0      ; │ 置黑
0x100097d8  mov byte [esi],   0      ; ┘
```

**规则**：
1. `R > G > B`（否则排除）
2. 饱和度 `> 0.09`（`0x1000d530`）
3. 色相分档结果在 10 项表内

三条全满足才保留，否则像素置黑。

### 4.5 色相分档 @0x10009360

与 `0x100027e0`（p27 的纹理分级）**完全同构**：

| 边界 | 值 |
|---|---|
| `0xd4f0` | 20.0 |
| `0xd4e8` | 40.0 |
| `0xd4e0` | 75.0 |
| `0xd4d8` | 155.0 |
| `0xd458` | 190.0 |
| `0xd4d0` | 270.0 |
| `0xd4c8` | 295.0 |
| `0xd430` | 316.0 |

同样按 `9*g1 + 3*g2 + g3` 打包（`0x10009463`..`0x1000949a` 的 lea 链）。

**但输入不同**：`0x100027e0` 收标准差，`0x10009360` 收**色相角（0–360）**。

配套常量：

| 地址 | 值 | 说明 |
|---|---|---|
| `0xd4f8` | 360.0 | 色相整圈 |
| `0xd500` | 60.0 | 色相一档 |
| `0xd510` | 3.0 | 值域下界 |
| `0xd520` | 5.0 | 值域上界 |
| `0xd528` | 0.16 | 饱和度上界 |
| `0xd538` | 0.3 | 第三档 |

> ⚠️ `0xd528`(0.16)、`0xd538`(0.3)、`0xd510`(3.0)、`0xd520`(5.0) 的
> **具体用途未逐条追踪**。它们出现在 `0x10009360` 附近但本文未确认
> 每个比较点。标为 OPEN（IMG25）。

## 5. 与 p22 / p27 的关系

| 说法 | 判定 |
|---|---|
| p22「颜色直方图/肤色」 | **部分对**：`0x10008e70` 不是肤色（过曝），但**另有真肤色检测**在 `0x100096c0` |
| p22「Haar + 肤色 + 轮廓 是一套」 | ❌ **仍错**：它们分散在不同 `CHECKEX*` |
| p27「`CHECKEX13x` 无肤色」 | ✅ **对**：`CHECKEX13x` 路径确实不含肤色 |
| 「整个产品没有肤色检测」 | ❌ **错**：`CHECKEX8x` 有，且是 HSV 判据 |

**教训**：从"某个函数不是 X"推不出"产品没有 X"。
p22 后期发现 `0x10008e70` 不是肤色，就下了"没有肤色"的结论——
但肤色检测在另一个函数里，用的是完全不同的方法（HSV 而非直方图）。

## 7. 对复刻项目的影响

`CHECKEX8x` 路径**尚未实现**。新增可复刻的内容：

| 项 | 值 | 状态 |
|---|---|---|
| 尺寸门槛 | 160 | 待实现 |
| 缩放目标宽度 | 160 | 待实现 |
| 特殊门控 | 宽==160 且 宽/高>20 → 返回 10 | 待实现 |
| ratio1 下界 | 0.08 | 待实现 |
| ratio1 分支点 | 0.15 | 待实现 |
| ratio2/ratio1 阈值 | 0.6 | 待实现 |
| 肤色前置条件 | R > G > B | 待实现 |
| 饱和度下界 | 0.09 | 待实现 |
| 保留色相桶 | {2,4,5,7,8,11,13,14,16,17} | 待实现 |
| 矩形分析阈值 | 0.54 / 252 | 语义未明，**不实现** |

**实现建议**：肤色判据可以完整复刻（`R>G>B` + 饱和度 + 色相桶查找），
但**矩形分析那段（`0x100094f0`）不建议复刻**——`0.54` 与 `252` 的
语义不明，且 `0x10005250` 是 C++ 对象，复刻它等于重写一个未知类。
