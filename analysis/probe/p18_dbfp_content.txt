# DBFP_Send/Recv 内容级过滤（P4 成果）

## 核心结论：产品做内容级 URL 过滤，非仅 IP/端口

DBFP_Send (0x5919) 的完整过滤链（按代码顺序）：

1. 总开关 0x1022800c == 2 → 放行
2. 策略1"禁止访问网络" → 进程名判定（0x1000367a）
3. IP/端口过滤（0x10228064 开关 + 0x1022806c 表，7字节/项）
4. **协议指纹检查**（0x10228024 开关）：
   - 0x10002006 遍历名单A（144B记录），strstr 匹配 0x10222180/0x10222184
   - 命中则拦截
5. **URL/域名过滤**（0x10228028 开关）：
   - TCP表取远端地址 → 小写化 → strcmp 匹配名单 0x102225a8
6. **端口检查**（0x5b12）：
   - strncmp(数据+4, 0x102225d4, 4)  ← 运行时字符串，比较前4字节
7. **内容级 URL 提取**（0x10005678）：
   - strncmp(data+4, "http://", 7)   ← 0x10222538
   - strncmp(data+4, "https:/", 7)   ← 0x10222540
   - 或 strstr 匹配 0x10222548
   - 提取出 URL 后查名单
8. 连接跟踪（0x1022803c/0x10228040 开关 + 0x10015200 表）

## 关键函数

| 函数 | RVA | 作用 |
|---|---|---|
| 0x1000ad00 | strncmp | 长度限制比较 |
| 0x1000ac50 | strncmp | 同上（另一变体） |
| 0x1000a8a0 | strstr | 子串查找 |
| 0x1000ab00 | strcmp | 完整比较 |
| 0x10002006 | 名单A遍历匹配 | 144B记录 strstr |
| 0x10005678 | URL提取 | 从HTTP数据提取URL |
| 0x1000367a | 进程判定 | Toolhelp快照 |
| 0x100053c0 | 远端地址获取 | TCP表遍历 |
| 0x100055e7 | socket查找 | 连接跟踪表32槽 |
| 0x10005622 | 分配槽位 | 连接跟踪表 |

## 连接跟踪表

- 基址 0x10015200，32 槽 × 16 字节
- 每槽：[socket句柄(4)][标志(4)][...8字节]
- 作用：记录已通过初始过滤的 socket，后续 Send/Recv 快速放行

## 协议头字符串（XNet2 下发，运行时填充 .uinitda）

| 地址 | 长度 | 推断内容 |
|---|---|---|
| 0x10222538 | 7 | "http://" |
| 0x10222540 | 7 | "https:/" |
| 0x10222548 | ? | 其他协议头 |
| 0x102225d4 | 4 | 端口/协议指纹 |

XNet2 侧确有 http:// (0x599e0), GET (0x699b8), POST (0x599d8), HTTP/1 (0x69985)。

| 地址 | 内容 |
|---|---|

| 0x102186d8 | 名单B（144B记录，计数0x10228124） |

## 复刻接口契约（网络+内容层）

1. LSP: dbfilter.dll WSPStartup → SurfGd.dll DBFP_*
2. 过滤层次：进程 → IP/端口 → 协议指纹 → URL/域名 → 内容URL提取
3. 拦截：返回0 + 错误码 10054
4. 状态：连接跟踪表 0x10015200
5. 名单：三组144B记录 + URL名单 + 进程名名单 + IP表
