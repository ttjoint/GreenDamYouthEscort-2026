## 1. CHECKEX13x 的骨架（@0x10007ea0，4,096 字节）

```
0x10007ea0  sub esp, 0x114                      ; 局部 276 字节
0x10007ea7  call 0x1000a021                     ; __chkstk / SEH
0x10007eb6  cmp [esp+0x120], 0x7ab7             ; ← 反调试守卫
0x10007ec1  je  0x10007ee8                      ;   首参必须 = 31415
0x10007ec3  push 0x2710                         ;   否则 Sleep(10000)
0x10007ec8  call dword ptr [0x1000c044]         ;   = Sleep
0x10007ed9  mov eax, 0x64                       ;   返回 100
0x10007ee5  ret 0xc                             ;   3 参数 cdecl

0x10007ee8  ... 取参数 2/3
0x10007efd  call 0x10004ec0                     ; 校验/构造图像对象
0x10007f28  call cvLoadImage (桩 0x10009e30)    ; ← 从路径加载图像
0x10007f52  fild [eax+0x28]                     ; 宽
0x10007f5a  fdivr [0x1000d578]                  ; 缩放比
0x10007f60  fimul [eax+0x2c]                    ; 高
0x10007f7f  call cvResize (桩 0x10009e2a)       ; ← 缩放到固定尺寸

0x10007f88  mov ecx, 0x50                       ; ← 尺寸门槛
0x10007f90  cmp [eax+0x28], ecx                 ;   宽 >= 80 ?
0x10007f93  jl  0x10007fb1                      ;   否则跳过
0x10007f95  cmp [eax+0x2c], ecx                 ;   高 >= 80 ?
0x10007f98  jl  0x10007fb1
0x10007fa5  call 0x100078e0                     ; ← 主判定
```

**关键事实**：
- 反调试守卫 `0x7ab7` 在**每个** `CHECKEX*` 里都有（`CHECKEX2` 同样，@0x10005a02）
- 图像**必须宽高都 ≥ 0x50 (80)** 才进入主判定
- 主判定 = `0x100078e0`，返回 `esi`，最终写入 `[ecx+4]` 后 `ret`

## 2. 主判定 @0x100078e0（完整逻辑）

### 2.1 门控链

```
0x100078ff  esi = [ebx+0x2c]        ; 高
0x10007902  edi = [ebx+0x28]        ; 宽
0x10007905  call 0x10008de0         ; 构造临时对象
0x1000790e  cmp esi, 0x20           ; 高 >= 32 ?
0x10007919  jl  0x10007a13          ;   否 → 返回 0
0x1000791f  cmp edi, 0x20           ; 宽 >= 32 ?
0x10007922  jl  0x10007a13          ;   否 → 返回 0
0x1000792b  idiv edi                ; 高/宽
0x1000792d  cmp eax, 8              ; 比例 <= 8 ?
0x10007930  jg  0x10007a13          ;   否 → 返回 0
0x10007939  idiv esi                ; 宽/高
0x1000793b  cmp eax, 8              ; 比例 <= 8 ?
0x1000793e  jg  0x10007a13          ;   否 → 返回 0
```

**注意**：这里是**整数除法**（`idiv`），所以 `8` 是硬边界。

### 2.2 直方图早退

```
0x10007945  call 0x10005150         ; 256 桶直方图 + 高亮度判据
0x1000794d  test eax, eax
0x1000794f  jne 0x10007a13          ; 命中 → 返回 0（放行）
```

### 2.3 双比值判定

```
0x10007960  call 0x10007140         ; 产出两个 double
0x10007965  fld  [esp+0xc]          ; ratio1
0x10007969  fcomp [0x1000d690]      ; 0.008
0x10007974  jne 0x10007a13          ; ratio1 <= 0.008 → 返回 0
0x1000797a  fld  [esp+0x14]         ; ratio2
0x1000797e  fcomp [0x1000d568]      ; 0.01
0x10007989  jne 0x10007a13          ; ratio2 <= 0.01  → 返回 0
0x1000798f  fld  [esp+0xc]          ; ratio1
0x10007993  fcomp [0x1000d418]      ; 0.4
0x1000799b  test ah, 1
0x1000799e  jne 0x100079d7          ; ratio1 < 0.4 → 走低分支
```

### 2.4 两个分支

**分支 A（ratio1 >= 0.4）**：`call 0x10001ba0` → 若返回非零则继续，
否则 `call 0x10008e10` 后 **返回 0x64 (100)**。

**分支 B（ratio1 < 0.4）**：

```
0x100079d7  fld  [esp+0xc]          ; ratio1
0x100079db  fmul [0x1000d6a0]       ; * 255.1020408163265
0x100079e1  fsub [0x1000d698]       ; - 2.0408163265306123
0x100079e7  call 0x1000a2b0         ; = ftol（截断取整）
0x100079f0  mov  esi, eax
0x100079fa  call 0x10008e10         ; 析构
0x100079ff  mov  eax, esi           ; ← 返回值
```

**分支 B 的数学等价**：

```
return (int)(ratio1 * 255.1020408... - 2.0408163265...)
```

注意 `255.1020408163265 = 1250/4.9`、`2.0408163265 = 10/4.9`，
即 `(ratio1 - 0.04) * 2500 / 9.8`。原厂没有写成这样，是从常量反推的等价式，
**仅作理解用，实现时应直接用两个常量**。

### 2.5 返回码语义

| 返回 | 条件 | 推测含义 |
|---|---|---|
| `0` | 任一门槛不通过 | **放行**（不判定） |
| `0x64` (100) | 分支 A 中 `0x10001ba0` 返回 0 | 命中（与 `CHECKEX2` 反调试返回值相同，可能复用为"已处理"） |
| `(int)(ratio1*255.1-2.04)` | 分支 B | **0–100 的评分**，具体含义未证实 |

> ⚠️ **`0x64` 的双重用途是推测**。`CHECKEX2` 在反调试失败时也返回 100，
> 但那是错误路径。这里返回 100 是正常路径。两者的数值相同不代表语义相同，
> 需要调用方（`XNet2`）的判定才能确定。标为 `OPEN`。

## 3. 分析流水线 @0x10007140

```
0x100075fb  free  (序号导入 0x8000c0cc → 49356)
0x10007605  free
0x1000779a  malloc
0x100077b9  malloc
0x10007872  free
0x10007878  free
```

### 3.1 灰度转换（@0x10007270–0x100072c3）

逐像素，`add eax, 3` 步进（**3 字节/像素 = BGR**），读三个字节后加权：

```
bl = [eax-1]   ; 第 3 字节
fild; fmul [0x1000d678] = 0.11
bl = [eax-2]   ; 第 2 字节
fild; fmul [0x1000d670] = 0.30
bl = [eax-3]   ; 第 1 字节
fild; fmul [0x1000d668] = 0.59
faddp; faddp
fadd [0x1000d660] = 0.5         ; 四舍五入
fstp qword ptr [ecx-8]          ; 存成 double
```

**权重 0.11 / 0.30 / 0.59 对应 BGR 顺序的 B / G / R**，
即标准 NTSC 灰度 `0.299R + 0.587G + 0.114B` 的近似版（精度降为 2 位）。

> 原厂用的是 `0.11/0.30/0.59` 而非 `0.114/0.299/0.587`。
> 差异很小但**不是同一个值**，复刻时必须用原值。

### 3.2 中心裁剪 + 标准差

```
0x10007477  取中心 (w/2, h/2)
0x10007487  左边界 = max(0, cx-3)
0x10007492  右边界 = min(w-1, cx+4)
0x100074a5  上边界 = max(0, cy-3)
0x100074b6  下边界 = min(h-1, cy+4)
0x100074f2  rep movsd 复制 7x7 窗口
0x10007525  call 0x10002790     ; 标准差
0x1000752a  fcomp [0x1000d658]  ; 1.4
```

**7×7 中心窗口的标准差与 1.4 比较** —— 这是纹理/清晰度判据。

## 5. 两个直方图函数是同一算法的拷贝

| 函数 | 大小 | 结构 |
|---|---|---|
| `0x10008e70` | 约 300B | `rep stosd 0x200` → 累加 `[0xd518]=1.0` → `/w*h` → 累加 `[0..0xd1]` 与 `[0xd2..0xff]` → 比 `[0xd540]=0.9` |
| `0x10005150` | 约 300B | **完全相同**：`rep stosd 0x200`、`[0xd518]`、`0x100` 桶、`0x100` 归一化、`0xd2`=210 桶分界、`[0xd540]` |

**结论**：`0x10005150` 是 `0x10008e70` 的内联副本（编译器未合并）。
两者语义相同：**R 通道 210–255 的像素占比 ≥ 0.9 → 命中**。

这进一步确认 P22 后期的更正：**不是肤色检测，是过曝/近白屏检测**。

`src/green_dam/imaging.py` 已按此实现（`HIGH_TONE_FLOOR=210`、`HIGH_TONE_THRESHOLD=0.9`）。

## 6. 更正：p22 标题的算法组合

p22 标题写「抓屏 + Haar 人脸 + 颜色直方图(肤色) + 轮廓形状分析」。

按本文实测，`CHECKEX13x` 路径的实际组合是：

| 环节 | 实测 | 状态 |
|---|---|---|
| 加载 + 缩放 | `cvLoadImage` → `cvResize` | ✅ 已还原 |
| 高亮度早退 | `0x10005150`（= `0x10008e70`） | ✅ 已还原（M4 已实现） |
| 宽高比 | 整数 `idiv`，阈值 8 | ✅ 已还原 |
| 灰度化 | 0.11/0.30/0.59 + 0.5 | ✅ 已还原 |
| **中心 7×7 标准差** | 阈值 **1.4** | ✅ 已还原 |
| **8 档纹理分级** | 20/40/75/155/190/270/295/316 | ✅ 已还原 |
| **权重表** | 8 项，4 项非零 | ⚠️ 来源未知 |
| 轮廓分析 | `cvFindContours` 等 15 个 | ⚠️ **在别的 `CHECKEX*` 里，本路径未用** |
| Haar 人脸 | `FImage.dll` | ⚠️ 独立模块，本路径未调 |

**重要**：`CHECKEX13x` 路径**没有**调用 `cvFindContours` / `cvCanny` / `cvHoughLines2`。
那些在 `CHECKEX3`–`CHECKEX8x` 里（见 p26 §7）。**不同 `CHECKEX*` 走不同算法。**

因此 p22 把两套算法写成一套是**错的**。
